# 问题修复

从仓库根读 `docs/README.md`、`docs/design/workflows.md#workflow-debug` 与 `#workflow-contract-evidence`，按现象加载必要契约及实际实现。核对比较 / 检出基线、暂存 / 未暂存 / 未跟踪与已有改动，保护无关工作。

- 记录输入、操作、预期 / 实际和环境，能自行复现就先做；异步控制完成顺序，性能固定规模与测量方式。沿相关跨模块路径验证原因假设，不先叠补丁。
- 复杂状态、调度、异步或跨层问题读取 `../form-deep-review/SKILL.md` 还原关键执行与状态；区分源码事实、运行结果、分析风险、契约缺口和测试缺口。作者总结与最终状态正确不足以证明整个过程正确。
- 实现违反契约直接修；歧义核对权威来源，新增 / 改变公共行为才转 `../form-design/SKILL.md` 集中讨论，仅暂停受影响部分，继续已授权独立工作。内部算法影响观察时机或错误传播时不能归入任意自主事项。
- 在授权范围实施最小修复：先观察反例能捕获原故障，修复后重跑原反例和必要相邻路径。不降低断言、跳过失败或改规范掩盖缺陷。没有生产实现时说明探针范围，不虚构 Runtime 修复。
- 按 `workflows.md#contract-verification` 关联契约、实现及真实测试 / 轨迹，在最终基线上复验审查发现后关闭；报告复现、根因、修改、命令 / 结果、未覆盖项和限制。重复问题交 W5，优先转成测试 / 静态规则。

交付检查按 `../form-delivery/SKILL.md` 裁剪，不强制设计归档或完整图表。没有已执行回归不声称修复验证完成；独立审查未执行如实披露。无需安装第三方插件。
