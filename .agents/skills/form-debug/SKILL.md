# 问题修复

从仓库根读 `docs/README.md` 和 `docs/design/workflows.md#workflow-debug`，按现象读取必要契约和实际实现；先看工作区差异，保护无关改动。

- 收集输入、操作、预期 / 实际和环境。能自行复现就先做，关键缺失再集中询问。异步控制时序，性能先固定规模与测量环境。
- 沿最短相关链路用日志、状态、测试和代码验证原因假设，不先堆补丁或无关重构。
- 实现违反契约直接修；环境故障修环境；歧义先核对依据；确需新增 / 改变公共行为才读 `../form-design/SKILL.md` 回到讨论。独立工作继续推进。
- 在授权范围实施必要修复，重跑原复现及必要相邻路径。回归应能捕获原故障，不只复制实现。没有生产实现时明确证据范围，不虚构 Runtime 修复或通过结果。
- 报告复现条件、根因、修改、实际验证与未完成项。交付检查按 `../form-delivery/SKILL.md` 裁剪，不强制所有问题走设计归档。

无需第三方插件；已有调试 skill 可补充方法，安装不作为前置。
