# 开发交付

从仓库根读 `docs/README.md`、`docs/design/workflows.md#workflow-delivery` 与 `docs/design/engineering.md`，按任务读治理中的实现准备和相关契约。先检查实际代码、清单、脚本与工作区，沿用已确认选型，不假设工程已初始化。

- 以现行主题作持续规格，引用章节，整合本次范围、公共接口、输入输出、身份 / 生命周期、错误、正反例和验收。不新建平行规范目录。
- 区分已确认原则、实现细化和真实阻塞。常规实现自主推进；公共行为缺口集中转 `../form-design/SKILL.md`，不猜测冻结 SDK，也不等 Platform / Studio 全部完成才做独立工作。
- 按依赖小批交付。低影响改动裁剪步骤与验证，不强制完整设计稿、无意义测试或逐步确认；多 agent 仅按任务需要和授权采用。
- 执行实际存在且适合改动的检查，失败后修复；新增工程按 engineering.md 初始化与兼容联验，不把计划命令当作已有脚本或安装成功。
- 跨层能力从输入到输出验证，UI 变更检查真实操作。候选 Schema / 探针、文档构建和占位目录不证明生产实现。
- 审查差异和必要文档 / 兼容影响，报告完成范围、运行方法、实际证据及限制。设计归档遵守确认边界；发布按用户授权的交付范围执行，不从 skill 推导权限。

第三方框架不是前置。新插件 / 工具安装先说明必要性和影响，由用户选择；不自动安装 Superpowers、OpenSpec 或 Spec Kit。
