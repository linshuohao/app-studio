# 开发交付

从仓库根读 `docs/README.md`、`docs/design/workflows.md#workflow-delivery`、`#workflow-contract-evidence` 与 `docs/design/engineering.md`，按范围读治理的实现准备和权威契约。先检查实际代码、清单、脚本、工作区与已有改动，沿用已确认工具，不假设初始化状态。

- 实现前只读预检，按 `workflows.md#implementation-preflight` 在当前任务给出：范围 / 契约章节、行为 / 不变量及正反例、影响 / 消费者、决策分类、行为切片与实际验证入口。引用现行主题，不复制长期规格或每步建文档。
- A 级公共语义沿用已确认原则，真实缺口集中交 `form-design`；B 级契约内方案自主选择并记录重要权衡；C 级局部组织直接处理。按对外行为影响判断，内部队列若改变通知 / 执行顺序也涉及 A。只暂停受影响范围，继续已授权独立工作，不等 Platform / Studio 全部完成。
- 范围契约有依据、真实阻塞已解决或明确排除、验收路径可执行时直接实现，预检不另设批准点。缺验证能力时可先在授权范围补齐，不能把未确认语义写成冻结 SDK。
- 按可观察行为小批贯通入口、状态、协作及输出，先让反例测试捕获缺失 / 错误行为，再实现并复验；执行实际适用命令，失败后继续修复。低影响文档 / 样式等裁剪为定位、修改和针对性检查，不增加重复实现的测试。
- 复杂状态 / 调度 / 异步 / 跨层一致性等变更读取 `../form-deep-review/SKILL.md`；审查者独立取证，基线变化后复核相关结论。普通变更做针对性差异审查。高风险的独立上下文按已有授权与能力采用，未执行如实披露。
- 按 `workflows.md#contract-verification` 将关键契约关联实现符号、测试 / 轨迹和实际结果；跨层能力从输入到可观察输出验收，UI 操作不能只用 Runtime Command 代替。区分源码事实、运行结果、推断与缺口，候选探针和文档构建不证明生产行为。
- 收尾报告完成范围、运行方式、重要权衡、最终基线证据、审查发现 / 修复复验和残余风险。P0 / P1 未关闭、必需门禁未通过或重要契约偏差未解决时暂缓合并；发布、外部操作依用户授权，不从 skill 推导权限。

设计变化按确认边界转 W1 / W2；实现偏差直接修复。第三方框架不是前置，新安装先说明必要性、影响及替代，由用户选择；不自动安装 Superpowers、OpenSpec 或 Spec Kit。
