# 方案讨论

从仓库根读取 `docs/README.md`、`docs/design/workflows.md#workflow-design` 与相关现行主题；这里的路径相对于仓库根。遵守根 AGENTS.md 的确认边界。

- 核对已确认原则、关联 ADR 与治理缺口，按议题加载必要上下游，不读全库或从生成 HTML 反推约束。
- 用真实场景串起目标、范围、正常 / 失败流程、职责、接口草案、取舍、正反例和验收。目标清楚时直接给完整草案，不默认逐问访谈。
- 新增可观察行为、真实跨层冲突与反例集中交用户选择；命名、容器和惯例整理为实现建议，不反复重开已确认原则。
- 草案在对话交付。完整专题未收敛时不逐段写规范或保存候选，除非用户明确改变要求；建议与验证通过不代表确认。
- 区分基线、建议、冲突和待确认结果。明确确认且获准归档后读取 `../form-design-maintenance/SKILL.md` 继续；只要求讨论时不自动编码。

无需第三方插件。已有合适澄清 / 领域建模 skill 时按需使用，避免强制访谈或额外审批。
