# 方案讨论

从仓库根读 `docs/README.md`、`docs/design/workflows.md#workflow-design` 与 `#workflow-contract-evidence`，按议题读取权威主题、关联 ADR、治理缺口及必要上下游。遵守根 AGENTS.md 的确认边界，不从生成 HTML 反推设计。

- 用真实场景一次串起目标、范围、正常 / 失败流程、职责、接口草案、状态所有权、副作用 / 观察时机、关键不变量、取舍与正反例验收，留下契约内实现自由度。目标清楚时直接给完整草案，不默认逐问访谈。
- 决策按行为影响分类：已确认原则不重问；新增公共语义、真实冲突和反例集中交用户选择；内部容器、命名、框架惯例由 agent 整理，调度等内部方案若改变可观察行为仍属语义决策。真实缺口只暂停相关部分。
- 区分设计意图、源码事实、运行证据和推断；审查发现是讨论输入，不能自动变成新契约。实现违反既有契约交 W4 修复，只有真实设计变化才继续 W1。
- 草案在对话交付，明确基线、建议、候选、冲突和待确认结论。完整专题未收敛时不逐段写规范或保存候选，除非用户明确改变要求；助手建议或验证通过不代表确认。
- 明确确认后按既有授权读取 `../form-design-maintenance/SKILL.md` 统一归档，不重复索取许可；实现准备衔接 W3 预检，但只要求讨论时不自动编码。

无需第三方插件；按需复用澄清 / 领域建模能力，避免强制访谈或额外审批。
