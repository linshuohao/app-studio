# 流程改进

从仓库根读 `docs/README.md`、`docs/design/workflows.md#workflow-improve` 与 `#workflow-evolution`，检查实际规则、skill、脚本和工具后推进。

- 用具体任务说明重复摩擦或重要失败，区分实现缺陷、契约缺口、流程遗漏和工具问题，提出可检验原因；不因单例叠加普遍规则。
- 给最小调整、预期收益、维护成本及撤回方式。建议请求先讨论，已授权修改直接完成；重大协作原则集中确认后统一归档，不重复索取已有许可。
- 优先修现有入口、skill 与脚本，按风险裁剪预检 / 审查产物。重复问题优先变成反例测试、静态规则或必要仓库约束，不复制第二套规范、每轮报告或逐函数台账。
- 同步 AGENTS、维护入口、受影响工作流 / skill、必要工程规则、演进 / 治理与来源。检查规则没有改变业务契约、扩大权限、让普通修改走完整架构设计或默认多 agent；第三方安装先说明用途、替代、影响与验证，由用户选择。
- 执行适用构建 / 同步、技能结构检查与场景试用，分别报告证据。隔离演练只说明对应场景，独立上下文未执行不能称通过；实际效率仍需后续真实任务，不擅自建立定时任务或遥测平台。
- 观察交付总时间、必要 / 无效设计中断、人工理解 / 纠偏、返工、可证实审查发现、契约 / 状态转换验证缺口、交付后缺陷及维护成本。只记录真实可得结果，无收益可合并、简化或撤回，不以代码量或规则数证明改善。

收尾区分规则已建设、基础检查、场景演练、真实任务已验证 / 待试用和未安装依赖；无知识变化报告无变化。维护流程按 README 执行，不能用结构校验冒充行为或生产验证。
