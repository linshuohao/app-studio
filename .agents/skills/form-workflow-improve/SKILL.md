# 流程改进

从仓库根读 `docs/README.md`、`docs/design/workflows.md#workflow-improve` 与 `#workflow-evolution`，检查实际 skill / 工具后推进。

- 用具体任务说明重复摩擦或重要失败，提出可检验原因；不因单例叠加普遍规则。
- 给最小调整、预期收益、维护成本与撤回方式。区分建议请求与实施授权；重大协作原则集中确认后归档，已授权实现不重复问许可。
- 优先修已有入口、skill 和脚本，不默认增加框架、平台、全局配置、自动化或多 agent。第三方安装先说明用途、替代、影响与验证，由用户选择。
- 结构 / 链接检查只证明基本可用，真实改善需要后续适合任务试用，不虚称提效，不擅自创建定时任务。观察交付总时间、人工纠偏、返工、缺陷及维护成本，不以代码量代替。
- 在现有说明、演进和本次结果记录实际变化，不建每轮报告；无收益可简化撤回。同步受影响 skill 与入口，按维护规则构建检查。
- 收尾区分本次已建设、真实任务已验证、仍待试用和未安装依赖。
