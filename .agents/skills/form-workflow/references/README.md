# form-workflow 按需工作方法

工作方法根据目标缺口选择。领域约束和编写参考由 [集中上下文](../../../context/README.md) 提供。

| 要解决的问题 | 打开 | 期待产物 |
| --- | --- | --- |
| 新行为、公共边界或取舍不明确 | [方案设计](design.md) | 有现状、方案、影响、反例和待确认点的完整讨论 |
| 用户已经确认现行知识更新 | [知识维护](maintenance.md) | 原文、必要生成视图、引用和实际检查同步 |
| 已授权实现 | [交付与验收](delivery.md) | 可验证切片、实际执行结果和范围说明 |
| 异常、回归或故障 | [定位修复](debug.md) | 最小复现、根因、修复及反例复验 |
| 核对差异、契约和执行证据 | [理解与审查](review.md) | 发现、覆盖、证据强度与剩余风险 |
| 反复遇到流程或工具问题 | [流程改进](improvement.md) | 改善点、反例检查和适用范围 |
| 恢复复杂变更或验收 OpenSpec | [项目适配](project-adapter.md) | 当前范围、证据与实际完成条件 |

例如修复 Studio 抽屉的键盘焦点：先解析 Studio 交互条款，复现并确认焦点归属，再打开定位与交付方法，运行相应浏览器路径。只有发现公共交互语义冲突时才进入设计讨论。
