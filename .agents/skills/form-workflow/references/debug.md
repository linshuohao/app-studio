# 定位与修复能力

读取时机：缺陷、回归、异步竞态、性能退化或工程故障。输入是现象、预期契约和准确基线；产出是根因、最小修复与回归证据，或有依据的阻塞。

按需读 `docs/design/workflows.md#workflow-debug` 与 `#contract-verification`、相关契约和实际实现。只有修复已授权时才写入；只读调查止于结论。

- 记录输入、操作、预期 / 实际与环境，能自行复现先做。异步控制完成顺序，性能固定规模与测量方法；沿相关跨模块路径验证原因假设，不先叠补丁。
- 复杂状态、调度、异步或跨层问题使用 [理解与审查](review.md) 的取证方法，区分源码事实、运行结果、分析风险、契约缺口和测试缺口。最终状态正确不能证明通知顺序或中间状态正确。
- 实现违反有效契约直接修；歧义先核对权威来源，只有新增 / 改变公共行为才把真实待决项交回统一入口。内部算法改变观察时机或错误传播时仍需要语义判断。环境故障定位环境，不强改业务规则。
- 在授权内实施最小修复：先观察反例能捕获原故障，修复后重跑原反例及必要相邻路径。不得降低断言、跳过失败或改规范掩盖缺陷；没有生产实现时说明探针范围，不虚构 Runtime 修复。
- 最终基线复验审查发现后才关闭，按风险采用 [交付与验收](delivery.md) 的验证要求，不重启另一条流程、不强制设计归档或完整图表。重复问题优先转成反例测试 / 静态规则，协作机制确有缺口再作为流程能力维护输入。

报告复现、根因、修改、实际命令 / 结果、未覆盖项及限制。没有已执行回归不声称修复验证完成；独立审查未执行如实披露。
