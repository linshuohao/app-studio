# 交付与验收能力

读取时机：当前请求授权实现、工程初始化、契约内重构或集成。输入是有效契约、范围与验收；产出是可观察行为切片及匹配证据。

从仓库根按需读 `docs/design/workflows.md#workflow-delivery`、`#implementation-preflight`、`#contract-verification` 和 `docs/design/engineering.md`。核对真实源码、清单、脚本与安装状态，沿用已确认工具，不假定项目仍未初始化。

1. 在原任务给出只读预检：范围 / 契约章节、行为 / 不变量及正反例、影响 / 消费者、阻塞与自主决策、纵向切片和实际验证入口。引用现行主题，不复制长期规格或每步建文档。
2. 范围有依据、真实阻塞已解决或排除、验收可执行时直接实现，预检不是额外审批。只暂停依赖未确认公共语义的部分；契约内细化自主进行，不等 Platform / Studio 全部完成，不把候选语义写成冻结 SDK。
3. 沿入口、状态、协作和输出小批贯通。先让适用反例测试捕获缺失 / 错误行为，再实现并复验；失败先核实原因。低风险文档 / 样式检查内容、链接、差异或呈现，不为此制造重复业务测试。
4. 按风险使用理解与审查能力，普通变更定向自查；复杂状态、调度、异步或跨层一致性采用已有授权的独立上下文 reviewer。输入原始契约、准确范围和验证入口，不输入预设结论；不可用时披露自审及残余风险。
5. 将重要契约关联实现符号和真实测试 / 轨迹。跨层能力验证输入到可观察输出，UI 操作不能只用 Runtime Command 代替；候选探针与文档构建不证明生产行为。遵守实际工程门禁，说明运行环境、最终基线、命令、结果与未覆盖项。
6. 交付前说明整体变化、前后行为、职责 / 执行链、取舍与源码入口，再给问题及最终证据；修复后更新模型，不能只追加“已修复”。P0 / P1 未关闭、必需门禁未通过或重要契约偏差未解决时暂缓合并。

并行只用于依赖和写入可隔离且有收益的工作包，重叠文件指定单一负责人；整合后验证真实连接，分包通过不等于集成通过。没有独立能力如实串行。

新设计、失败或证据缺口交回统一入口按原目标处理，不调用旧 workflow 别名。第三方安装、提交和发布分别核对当前授权；工具与正式变更规则只维护在 [项目适配](project-adapter.md)。
