# 方案与契约能力

读取时机：目标、场景或公共语义不清，或真实设计冲突影响当前请求。输入是当前目标、有效契约和未知；产出是完整草案、有依据的判断及集中待决项。下一步始终由统一入口根据授权决定。

从入口解析当前阶段和领域条款。涉及新决定、冲突或未确认语义时，按条款来源核对相关现行正文、ADR、治理缺口及必要上下游。

- 用真实场景串起目标、范围、正常 / 失败路径、职责、接口草案、状态所有权、副作用 / 观察时机、关键不变量、取舍与正反例验收，留出契约内实现自由度。目标清楚就给完整草案，不默认逐问访谈。
- 先查已有依据，再识别影响当前切片的关键未知。需要调查或实验时明确问题、授权、资源边界、隔离与退出条件；未知不再阻碍当前目标就停止探索，不要求全部远期设计完成。
- 已确认原则不重问；新增公共语义、真实冲突和反例集中交用户选择。内部容器、命名、框架惯例自主整理；内部调度影响可观察行为时仍是语义决定。
- 草案先在对话交付，区分已确认基线、源码事实、运行结果、推断、候选、冲突和待确认结论。完整专题未收敛时不逐段改规范或保存候选，除非用户明确改变要求；助手建议或验证通过不是确认。
- 实现违反既有契约是修复输入，不重开架构；只有真实设计变化才要求新的语义决定。明确确认后，统一入口按已有授权使用知识维护能力，不重复索取归档许可；仅讨论不自动编码。

无需新增第三方插件。澄清、领域建模或技术分析方法按实际缺口使用，不把方法变成额外审批。
