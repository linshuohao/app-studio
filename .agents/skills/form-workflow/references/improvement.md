# 流程能力维护

读取时机：协作规则、skill、验证环境或工具存在明确改进需求。输入是实际任务、摩擦证据或明确用户请求；产出是最小调整、检查与真实效果状态。这里的对象是工作方法，不是产品业务工作流或引擎调度。

按需读 `docs/design/workflows.md#workflow-improve`、`#workflow-evolution` 与实际受影响规则 / 脚本 / 工具。

- 区分实现缺陷、契约缺口、流程遗漏和工具问题，给可检验原因；已有行为正确就保留，不制造失败来证明新方法更好，不因单例叠加普遍规则。
- 给出最小调整、预期收益、维护成本和撤回方式。建议请求先讨论，明确授权的调整直接完成；重大新增协作原则集中确认，已有授权不重复询问。
- 优先修现有入口与工具，重复问题转成能捕获反例的测试、静态规则或必要仓库约束；不增加平行规范、每轮报告或逐函数台账。
- 仅同步本次授权范围。若只改 skill，只写 `.agents/skills/`，范围外 AGENTS、docs、脚本、OpenSpec 不改，具体不一致如实报告；不因通用归档程序扩写。不改变业务契约、扩大权限、默认多 agent 或让小改动走完整架构讨论。
- 分开验证技能结构 / 链接、场景应用、宿主发现、第三方方法组合和真实任务结果。第三方安装先说明用途、替代、影响及验证，由用户选择；缺失工具不自动下载补齐。
- 效果观察只用真实可得结果：总时间、必要 / 无效中断、人工理解 / 纠偏、返工、可证实发现、状态转换验证缺口、交付后缺陷及维护成本。无收益可合并、简化或撤回；不以代码量 / 规则数量证明改善，不擅自建立监控、定时任务或遥测平台。

收尾区分规则已建设、基础检查、隔离演练、真实任务已验证 / 待试用与未安装依赖。本轮调整完成不等于长期提效，无知识变化不创建空维护记录。
