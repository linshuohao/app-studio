# 确认后的知识维护能力

读取时机：完整专题已明确确认，或用户明确授权维护现行知识。输入是可追溯的确认范围与现行材料；产出是正确归位的知识和真实检查结果，不代表实现或人工验收完成。

按下面的项目维护方法执行。人读手册源位置是 `docs/README.md#incremental-maintenance`，维护或追溯时可定位原文。

- 核对会话确认范围与授权，已有确认继续有效；部分确认不扩大，候选保留身份。审查发现、助手建议和验证通过不自动成为设计决策。
- 修改前核对暂存、未暂存、未跟踪及既有改动，必要时留快照区分本轮增量。分类知识变化，检查必要上下游，仅修改授权范围的 Markdown / 样本源及派生物。
- 保留设计意图、行为 / 不变量与验收关联，按影响同步 ADR、演进、治理、术语和来源。重要决策替代保留旧 ADR 及双向关系；普通澄清不强建 ADR，搬迁遵循 `relocated_sections` 与保留检查，不删减必要设计说明。
- 契约调整影响现有实现时列出后续验证需求，不能凭归档关闭代码缺陷。状态以契约闭环和实际证据为准，不把文档量等同完成度。
- 优先用 `.venv-docs/bin/python` 执行 `tools/docs/build_docs.py` 和 `--check`；协议样例变化另跑 `docs/validation/run_validation.py`。呈现变化做实际渲染检查，未执行不得称通过。
- 源条款、路由或生成器变化时运行 `.venv-docs/bin/python tools/docs/build_contracts.py` 和同命令的 `--check`。核对派生条款、命中原因和受影响消费者。生成视图只含生效条款。
- 核对最终差异、稳定 ID / 锚点与内容保留。按 README 报告真实文件、ADR、一致性、状态、命令 / 结果与未完成项；无知识变化报告无变化，不创建空报告。

归档不自动授权编码、修复、提交或外部发布。若请求范围仅限 skill，则不得借维护能力修改规范或生成 HTML；说明范围外同步项即可。需要实现时由统一入口核对授权和当前切片。
