# 项目载体与工具适配

读取时机：恢复任务、维护正式成果、采用 OpenSpec / Superpowers 或判断证据是否仍适用。编排由 `form-workflow` 负责，本文件仅给项目事实归属与工具约束。

## 唯一事实载体

| 信息 | 沿用位置 |
| --- | --- |
| 项目边界、运行 / 门禁 | `AGENTS.md`、`docs/README.md`、`docs/design/workflows.md`、`engineering.md` |
| 现行设计与公共契约 | `docs/design/` 对应主题，唯一权威正文 |
| 已确认决策、替代、状态与来源 | 现有 ADR、演进、治理、术语及来源 |
| 本轮范围、计划和证据 | 当前任务 / 既有 PR；复杂变更用原 OpenSpec Change 与单一 `tasks.md` |
| 导读和交接 | 对话或原任务，引用上述原始材料 |

未确认完整专题仍在对话交付，不新增候选稿、平行计划或每轮报告。恢复时核对目标、范围、验收、契约 / 授权、Git / Diff、成果和未决项，不能只凭摘要或任务勾选继续。

## OpenSpec

真实规则读 `docs/design/workflows.md#workflow-openspec`，命令 / schema 以仓库和实际安装为准。复杂变更复用当前相关 Change 与 `form-change`；轻量任务不强制建 Change。独立 ai-co 不是运行依赖，不更换本项目 schema、命令或 hooks。

- `docs/design/` 保持唯一主规格；Change 只保存当前范围、验收增量、实施设计、单一任务和必要证据。禁止默认 sync 或向 `openspec/specs/` 写主规格，不复制 `docs/superpowers/plans/`。
- 新专题确认后才落盘。实施中实质变化检查上下游、重开受影响任务、撤销相应证据并标记审查过期；仍适用的成果明确复用。取消 / 缩减不能勾选为成功完成，也不走成功归档。
- 恢复时核对真实 Git 与契约基线。相关文件或执行环境变化后复核证据适用性；旧绿测 / Change 文件齐全不能证明最终版本通过。
- 归档前完成确认后的知识维护、适用验证与审查，通过 `python3 tools/engineering/workflow.py verify <id>` 和 `archive <id>`，由项目适配器使用 `--skip-specs`；不以 `--no-validate` 绕过检查。上游跳过主规格不免除自定义 schema 的必需产物。
- 收据只证明所列范围和检查，不证明范围完整、用户确认、独立审查或语义正确；未关闭高影响问题照实保留。

## 方法与权限

Superpowers 等只按当前缺口采用实际可用方法，先读其真实入口与正文。已有 Design / Tasks 足够时复用；只有一个当前编排者，不重跑已经完成的讨论或复制计划。与宿主、用户要求或项目约定冲突时按真实指令优先级处理，无法兼容的具体动作如实报告；不修改第三方原件，不声称已控制其自动触发。

工具缺失先用已授权替代完成独立部分，强制能力缺失报告具体阻塞；不伪造调用、独立审查或通过记录。不因加载 skill 自动安装；另有安装请求时仍执行项目说明与权限程序。

高风险独立 reviewer 的既有授权继续有效。项目原有阶段本地提交策略不因入口迁移撤销，实际执行仍核对当前任务授权、范围、检查及最新限制；本次若要求不提交则不提交。只提交明确归属本任务的改动，混合文件按补丁隔离，不能 `git add .`。Push / Merge / 发布、安装、共享和外部通信分别遵守对应授权，方法不授予权限。

结构检查、隔离场景、宿主发现与真实业务闭环分别报告；无后台常驻监听或必然自动触发的保证。
