# 理解与深度审查能力

读取时机：单独只读审查、复杂行为理解或交付中的高风险验证。输入是原始契约、完整相关源码、准确 Diff 与检查入口；产出是可理解、有证据的判断。**单独审查保持只读，不修改业务代码、测试或规范，不自动修复 / 归档 / 提交。**

按需读 `docs/design/workflows.md#deep-review`、`#contract-verification` 与适用工程门禁。解释只是导航，不能代替独立证据。

1. 固定比较提交 / 检出版本和范围。工作区覆盖暂存、未暂存、未跟踪、新增 / 删除 / 重命名与生成物；每个变更文件记录审查单元、方式和状态，排除 / 未审项说明原因。沿行为路径读取必要未修改实现与消费者，必要时留快照。
2. 还原职责、入口出口、API / 依赖、状态所有权与副作用；复杂交互给源码定位的时序、状态图或表，覆盖分支、调度 / 通知、错误、重入、取消 / 失效和清理。标明源码推导或真实轨迹，普通文件不强制完整图表。
3. 先从契约与源码独立取证，再核对作者说明。每项问题给触发条件、影响、依据、文件 / 符号 / 行号、证据类型与验证状态；分开已证实缺陷、条件性风险、契约缺口和测试缺口。文件读过不等于行为已验证。
4. 运行适用的现有检查，反例明确输入、顺序和断言。只读审查需要新增测试时交付具体建议，由统一入口核对修复授权；临时隔离探针仍需已有授权并说明局限。不得降低断言或修改规范迁就实现。
5. 收口复核基线。变化后重审受影响路径，未复核标为过期 / 未验证；修复后的发现需最终基线复验再关闭。按 P0 / P1 / P2 列缺陷，其他风险 / 缺口另列；P0 / P1 未关闭、必需检查未通过或重要偏差未解决时暂缓合并。

面向用户按“整体变化与设计 → 基线 / 覆盖 → 问题及行为链 → 验证与结论 → 修复后最终模型与限制”展开，严重紧急问题可先提示。只在当前任务 / 既有 PR 交付，不默认建报告文件；无发现仅说明本次范围未发现，不推断全局无缺陷。

高风险审查沿用项目已有独立 reviewer 授权和实际能力，无法独立执行时披露自审与限制；独立上下文不保证没有共同盲点。例如稳定后通知，需定位全部通知调用及观察者所见状态 / 顺序，不以最终状态绿测代替过程证据。

核实发现后，真实语义缺口、已授权实现偏差或补证需求都返回统一入口判断下一项工作。只读请求不因此获得写入权限。
