# 五类任务与统一入口的能力对照

读取时机：解释迁移范围、处理旧入口引用或继续迁移前的任务。本项目采用 ai-co 0.2.0 的共同事实、按缺口连续执行、人的理解和证据有效性方法；这里是项目适配，不依赖其他项目的绝对路径或安装副本。

**统一的是编排，不是删掉项目能力。** 五类任务全部由 `form-workflow` 选择下一步；旧流程编号用于理解既有文档和工作类型，不再是独立状态机或串行必经阶段。

| 旧流程 | 被新循环替换的部分 | 必须保留的项目能力 | 结论 |
| --- | --- | --- | --- |
| W1 方案讨论 | 恢复背景、识别未知、选择分析 / 讨论、提出决定、判断何时结束 | 完整专题草案、A/B/C 语义权限、确认前不落盘、已确认原则不重问 | 编排可替换；方案 / 确认约束保留为 design 能力 |
| W2 确认归档 | 何时归档、恢复上下文、归档后的继续 / 结束 | README 统一维护、现行主题 / ADR / 治理 / 来源归位、构建、内容保留与确认范围 | 不能用通用循环替代维护程序；保留 maintenance 能力 |
| W3 开发交付 | 预备、切片、实施、审查、补证、修复与交付的循环 | 项目只读预检、契约映射、生产路径和工程门禁、当前 OpenSpec 适配 | 主流程可替换；保留 delivery 项目验收要求 |
| W4 问题修复 | 反馈核实、根因调查、修复、复验和语义升级 | 可控复现 / 反例、最小修复、异步与跨层取证、不得改规范掩盖缺陷 | 主流程可替换；保留 debug 专项方法 |
| W5 流程改进 | 发现问题、选择最小改动、执行、验证及效果回看 | 规则变更范围、兼容性 / skill / 工具检查、真实效果与成本判断 | 不再独立编排；保留 improvement 专项能力 |

W3 / W4 与新循环重合最多，可直接收敛；W1 的通用探索也被接管。W2 是项目知识治理程序，W5 是对协作方法本身的维护，两者不能只靠通用循环就宣称能力已替代。深度审查不计入原五流程，保留 review 能力并遵守只读边界。

## 唯一入口与旧名称

- 新任务自然语言或显式 `$form-workflow` 使用唯一入口；W1–W5 仅为任务类型标签，不要求用户选择或顺序执行。
- 原 `$form-design`、`$form-design-maintenance`、`$form-delivery`、`$form-debug`、`$form-workflow-improve`、`$form-deep-review` 六个 skill 目录和兼容指针已移除。历史任务出现旧名称时使用统一入口，不读取旧路径或重建别名。
- 方案、归档、交付、修复、改进、审查分别保留在 `design.md`、`maintenance.md`、`delivery.md`、`debug.md`、`improvement.md`、`review.md`。只读调查不写入，单独审查不自动修复 / 归档 / 提交，仅归档不自动编码，建议请求不自动改规则；能力选择不扩大授权。
- `AGENTS.md`、根 README、`docs/README.md`、工作流正文、工程门禁及 OpenSpec schema 同步使用统一入口。历史来源仍保留当时的名称，不代表现行调用方式。
- 统一入口保留隐式选择元数据；文件检查不等于宿主已刷新技能列表或实际自动调用。独立 ai-co 项目、全局 skills 与第三方插件不在本次迁移范围。
