# ADR-FE-007：逐 Command 逻辑观察与相对 Scope 位置



## 背景与问题 {#adr-007-context}

整对象导入不一定改变其内部被观察字段，数组移动改变位置也不等于同一人的年龄改变。不可变旧 Root 保住旧 Data，却不能自动保住原地修改的 Scope 旧位置。需要在变更边界解决比较，不把移动历史传给每条规则或 Renderer。

## 已确认原则 {#adr-007-decision}

每条 Command 取得前后 Data 与可稳定读取旧绑定的 Scope 视图，一致提交 Data / Scope 后定位候选，再比较同一逻辑观察目标。相对观察沿同一 ScopeId，固定路径观察同一位置。ChangeContext 只服务当前 Command，比较后释放，不进 pending 或沿规则链传播 ScopeChange。

ScopeId 与下标分离。Scope Index 的位置事实是父 Scope + 相对集合位置 + 本层位置，绝对路径按需解析；父移动不重写所有后代路径。Dependency Index 查观察者，Scope Index 查身份与位置，辅助索引不能成为第二个独立事实源。L1 不建全局词法注册表与 L3 实例登记并不冲突。

## 推荐方案与取舍 {#adr-007-options}

来源比较过周期全量快照、每规则保存上次执行参数、当前 Command 前后 Root，确认最后一种原则。前两者分别增加全表历史成本或常驻参数缓存，而且不准确代表上条 Command。逐条检测保留 25→26→25 两次失效，最终值相同也不撤销已有 pending。

Object.is / 存在性比较、Trie + 模板、局部旧 ScopeReadView 仍为**推荐**；不能因来源正文写“已收敛具体结论”就高于其决策表状态。推荐引用比较避免全表深比较，代价是整对象新引用可保守失效；子字段同值可跳过。Trie 的真实成本取决于深度及命中的观察者，不能宣称所有操作恒定时间。

整行对象替换保留行身份，嵌套结构另行处理；整数组替换重建已确认，不按业务 ID 或内容协调旧身份，即使数据相同也是新实例。删除回收旧实例，真实新实例才应用激活策略。Host 输入对象防御、连续结构操作与旧位置可信度仍需验证。

### 2026-10-20：观察比较与数据边界确认

已确认按观察位置比较，基本值按值 / 存在性，对象 / 数组按引用，不默认深比较；JS Object.is 及跨端细节仍为实现固化项。

外部输入的对象 / 数组值进入引擎时复制，解除 Host 原对象与内部数据的可变别名；内部以不可变 Root 和结构共享更新。read / snapshot 返回只读契约，不在生产环境为每次读取深拷贝或默认增加代理。开发环境递归冻结引擎持有的业务数据，捕获误写，不冻结 Host 原对象、Scope Index、Pending 或其他内部可变管理结构。Command 必须先构造修改路径上的新容器再写入，不能原地修改冻结的旧对象或数组；新数据发布前冻结，未变化且已保护的共享子树可复用。生产环境违反只读契约属于错误使用，不保证绕过 Command 修改后的状态正确。

对 JSON 树形输入，复制耗时与新增内存均为 O(n)，n 是本次传入值的规模：初始化整表按整表规模，替换大数组按该数组规模，标量写入没有深拷贝子树。不是每条 Command 深拷贝全表。路径容器复制另受路径深度及各容器宽度影响，不能宣称固定 O(depth) 或常量成本。开发冻结遍历所保护数据，首次全量通常 O(n)，后续应跳过已冻结共享子树；Object.freeze 仅浅冻结，嵌套保护需遍历。实际延迟与峰值内存须由目标设备基准测量，未做生产实现或性能测试。

记录见 [数据边界](../design-history.md#data-copy-freeze-update)。该轮未确认数组双定位；后续确认见下方数组位置契约。

### 2026-10-20：数组数字与锚点位置契约

数组插入 / 移动的目的位置同时支持数字下标与稳定成员锚点（成员之前 / 之后）。移动对象按稳定成员身份指定，数字只描述目的位置；位置在 Command 实际执行时按当时数组解析。移动的数字目的位置指移动后的最终下标，例如 [A,B,C] 中将 A 移到 2，结果为 [B,C,A]。长度为 n 的数组插入位置为整数 0…n，n 表示追加；已有成员在同一数组内移动的最终下标为整数 0…n−1。

位置越界、非整数、目标锚点已删除或不属于目标数组等位置失效必须明确返回结构性失败，不自动夹到首尾，不回退追加或猜测其他成员。单次操作在解析 / 校验位置后再一致更新 Data 与 Scope，失败不留下半完成的移除状态；失败不回滚 batch 中先前已成功的其他 Command。锚点与数字位置共用同一结构执行机制，正式字段 / Union、错误编码及精确返回结构继续固化，不新增命令种类。

双定位降低排序组件与稳定身份调用的接入转换成本，统一在内部执行；最终下标避免调用方补偿移除造成的位置偏移，明确失败避免静默改变调用意图。用户已确认三项方向，记录见 [数组位置](../design-history.md#array-position-update)。
