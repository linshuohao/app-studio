# ADR-FE-026：单团队空间与内建角色授权

## 背景与决定 {#adr-026-decision}

用户希望在功能设计前先确定授权框架，并避免细粒度权限造成配置负担。用户选择单团队共用空间、RBAC、少量内建角色，随后确认完整方案及表单管理 / 工作台的权限映射。采用空间成员上的角色分配与明确资源归属；查看者、编辑者、发布者、管理员组合五组业务权限，不按按钮拆分，也不开放自定义角色、直接用户授权或角色继承。

编辑与发布分离，兼任者可组合角色；管理员拥有当前明确权限，不能绕过编译准入。团队表单共享，创建人不自动形成独占权限。撤权后新请求用最新权限，延迟发布实际变更前重新检查；最后一个有效管理员受并发保护。

## 取舍与后续 {#adr-026-consequences}

相比逐资源 / 逐操作自由授权，内建角色降低管理成本，但首期不支持私有表单或定制岗位权限。相比单一全局角色字段，空间成员关系和资源归属增加少量模型约束，保留以后多团队独立授权的边界，不预建多租户产品。

完整行为、操作映射和反例验收统一见[权限专题](../platform-studio.md#platform-rbac)。身份服务、存储、页面与 API 待设计；本次没有实现或运行验收，不决定 DDD 或微服务架构，不替代引擎 / Host 既有边界。
