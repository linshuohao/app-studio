# ADR-FE-028：最小创作 MVP 与不可变编辑修订

> 当前规则由 [ADR-FE-029](ADR-FE-029-platform-config-versions.md)承接。下文保留原决策。

## 决策与依据 {#adr-028-decision}

用户要求最简 MVP，不做实时协作；保存冲突时可新开分支或确认更新当前分支，并澄清“覆盖”是版本更新而非抹除旧内容。随后明确确认并授权统一归档。

采用表单组织分支，分支持有最新编辑修订指向，草稿表示编辑状态。每次成功保存追加不可变修订并更新分支指向，错误或未完成配置也可保存；检查通过是构建 / 发布准入，不是保存准入。确认覆盖追加修订而不自动合并，原修订保留；确认期间又发生更新则重新提示冲突。恢复历史内容也追加新修订。

Fork 可从确定历史、已保存快照或明确选择的本地内容创建新分支，也可生成独立表单；首期不做自动合并。发布版本不可变，Host 按 releaseId 显式消费，不本地拼接 formId 与版本生成新的发布身份；动态发布入口后置。表单列表、工作台及版本详情承载首期操作，沿用 RBAC 与模块化单体。

## 替代、代价与范围 {#adr-028-consequences}

替代讨论中的“一个表单仅一个共享草稿”“普通保存不生成修订”“仅检查通过才留存修订”“冲突只能另开分支、不能覆盖”“覆盖丢失旧草稿”“仅允许从确定版本 Fork”等候选。旧候选不是 accepted ADR，无需伪造旧决策的 superseded 关系。ADR-FE-026 / 027 的权限、边界与部署规则保持有效。

追加历史增加存储成本，但避免更新后丢失团队旧内容。它不是自动语义合并：新内容可能未包含被覆盖修订的修改，旧内容仅保证留存可追溯。具体存储去重和接口可自主设计，不能以内部优化删除本次承诺的历史。不开启完整 Git 产品、实时协作、审批或分支级权限。

完整模型、流程、反例和验收见[创作 MVP](../platform-studio.md#platform-authoring-mvp)。此次仅归档设计，不证明平台接口、持久化、发布或 Host 装载已经实现；身份来源、存储方案、加载方式与接口细化进入实施准备。
