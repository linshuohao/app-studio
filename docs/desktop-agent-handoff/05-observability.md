# 05 · 本地记录与 Langfuse

本地轮次记录负责恢复和用户可见进度。Langfuse 通过 JS/TS SDK 的 OpenTelemetry 集成观察同一轮次。选定服务端版本后，再按官方兼容表锁定 SDK 版本。 [Langfuse SDK 与兼容说明](https://langfuse.com/docs/observability/sdk/overview)

| 单位 | 记录内容 |
| --- | --- |
| 一轮 Agent 执行 | 一个 trace，关联随机轮次标识、应用版本、执行时长与终态 |
| 一次实际模型请求 | 一个 generation，记录模型、延迟和可用的 token/usage 计数 |
| 一次工具或编译检查 | 子 observation，记录工具类型、诊断数量、分类、耗时及结果 |
| 一次修复或失败 | 跟踪尝试和结构化错误类别；取消有独立结果 |

观测优先在 Worker 的任务边界手工记录。模型以包装后的调用入口记录，工具在受控执行器记录。若启用框架自动观测，确认不会重复产生 generation。跨进程需要关联时传递必要的 trace 标识或 OTel 上下文。原始 Pi 事件留在应用映射层。 [Langfuse 自定义观测与嵌套](https://langfuse.com/docs/observability/sdk/instrumentation)

默认关闭远端上报。启用后仅允许结构化字段白名单，排除需求原文、候选内容、本地路径、凭证与数据快照。业务错误以类别和诊断数量呈现。模型输入的外发确认与遥测开关独立。SDK 密钥不得打包进桌面分发物。开发可用独立项目配置；公开分发前决定由用户配置自己的端点，还是经受控转发服务接入。

上报异步且有界；退出只做有限等待。丢弃遥测不改变轮次结果。用计数器或本地事件说明导出失败，测试关停、断网、取消、脱敏和 token 字段缺失。首批真实后端验收用合成输入，核对一轮 trace 的父子关系及上报字段。
