# 06 · 落地顺序与验收

先把一条链跑通。每批报告实际命令、依赖版本、输入、结果和剩余缺口。

启动前登记三类输入的来源与版本：引擎依赖及制品摘要、旅险 Definition 与能力目录、工作台交互及其现有回归用例。按[引擎设计](07-engine-design.md)定位协议、算法和包入口，按[工作台设计](08-workbench-design.md)定位 Studio 的源设计与测试。涉及既有行为的变更，以原仓契约和真实引擎测试为验收依据。

| 批次 | 交付 | 通过条件 |
| --- | --- | --- |
| **0 兼容性** | Electron 安装包最小入口；Pi Worker 一次流式调用；Langfuse 测试 trace；独立引擎制品装配 | 在打包后的进程中记录实际 Electron/Node 版本。用正式依赖锁验证 Pi 工具与取消，确认 Langfuse SDK/服务兼容，安装引擎制品并跑最小表单。 |
| **1 纵切** | 单个旅险项目，确定性模型替身，候选经 Compiler 审阅后保存 | 模拟澄清、成功与诊断失败。应用一处差异，试填后保存并重开，核对快照与定义各自的状态。实际模型测试单独记录。 |
| **2 编辑** | 布局编辑及 JSON 往返，然后字段、联动与校验 | 画布增删、抽屉修改、撤销、窄窗焦点。移动跨 Scope 节点时保留含义或给出拒绝原因。 |
| **3 恢复与遥测** | 取消、中断、保存冲突和可选 Langfuse | 晚到结果被忽略；重开保留完成记录；关停遥测或断网上报失败时本地编辑保存仍通过。 |
| **4 打包** | macOS 安装包与一条真实旅险生成验收 | 从安装包启动，用真实模型完成一轮。保存重开能读回确切修订。只有完成相应签名与发布验证后才可称为可分发。 |

## 最小反例

第 2 批需单独走查[字段 Schema 编辑](09-field-schema-design.md)的护照号规则及引用保护，以及[共享表达式配置](10-expression-design.md)的三个消费入口、错误类型和取消后的迟到响应。由实际工作台完成应用、撤销、保存重开。

- 旧修订上的候选不能覆盖较新的人工修改。相同保存请求重试不会创建第二条修订。
- 取消发生在模型流、工具调用或编译检查后，迟到进度不会改变当前状态。
- 运行环境不兼容时给出真实错误，UI 可继续打开并编辑已有项目。
- 物料和纯函数能被真实 Compiler 检查、被运行端装配，并在合成旅险场景产生预期结果。
- 遥测启用时对上报载荷断言，证明原始需求、候选、路径和凭证均未出现在记录中。

MVP 用确定性测试夹具验证失败与成功，真实模型用于用户场景及打包联验。第 0 批未拿到引擎制品时记录供应缺口，桌面到真实引擎的里程碑按实际结果核验。
