# 09 · 字段 Schema 编辑设计

字段分区编辑 `data.schema`。字段行提供结构操作，属性和条件配置统一进入抽屉。定义级业务 Constraint 继续在[校验分区](08-workbench-design.md#校验)维护。

## 入口、窗口与导航

| 状态或位置 | 作者怎么操作 |
| --- | --- |
| 表单结构 | 根、对象、数组、数组元素与叶字段出现在树中。字段名称靠左，类型和必填在宽树靠右，窄树移至下一行。长名称在树内横向滚动。展开与选中分别操作。 |
| 共享定义 | 独立展开 `$defs`。从引用字段可查看目标，从共享定义可查看确定的直接和经数组元素的间接使用位置。返回时恢复原字段选择与树滚动。 |
| 节点操作 | 行内提供该节点允许的新增子项、同级插入或删除；按当前位置保持顺序。根模型不显示删除。删除前呈现受影响的引用，复杂或歧义位置提供原文入口。 |
| 字段配置 | 编辑与只读查看共用右侧 640 px 抽屉。页头和底部操作固定，正文滚动。控件常用高度 32 px，标签间距 8 px，字段间距 12 px。短项可并排，窄窗改成单列。 |
| 返回路径 | 关闭浮层恢复焦点。先从字段进入所属对象的条件、再返回时恢复原字段位置。整份 JSON 返回原阶段时恢复分区、节点和可恢复滚动。 |

## 抽屉内四组配置

| 分组 | 控件与代表性写回 |
| --- | --- |
| 基础属性 | 字段标识通过「改名」进入操作，先看使用位置。名称与说明分别填写。类型用一个多选 Select，零项省略 `type`，单项写字符串，多项写数组。默认值开关与类型化输入区分未设置、空字符串、0、false 和 null。 |
| 校验属性 | 「始终必填」写父对象 `required`。字符串长度、数组项数用非负整数，数值边界用比较符和数字。已有含边界与不含边界时同时回显。允许值逐项编辑并保留 JSON 类型。高级相关限制折叠显示已配置项。 |
| JSON Schema 联动校验 | 「如果／成立时／否则」在声明节点维护。等值条件同时声明触发字段存在。`dependentRequired` 表达存在性触发的必填，`dependentSchemas` 表达存在性触发的子模型。组合区区分 `allOf`、`anyOf`、`oneOf`、`not`。每个分支可进一步配置子模型，也可打开局部 JSON。 |
| 高级属性 | 折叠并提示已配置项。`format` 作为格式注解。`pattern` 可手写、选模板、用单条样例试跑，样例留在会话且试跑可超时终止。示例保持 JSON 类型，只读、只写和弃用均区分未设置、是、否。资源标识、锚点和动态引用独立收起。 |

引用字段默认显示身份、引用目标和跳转入口，局部约束放在「本字段覆盖」。换目标保留当前节点的覆盖及其他引用。复杂外部或动态引用按原文定位，无法确定使用范围时保留这一状态。

## 从护照号看到条件属于谁

在旅险根模型中配置「出境需要护照号」。用户从护照字段看到关联规则，点「编辑所属对象」后进入根模型。下面片段写入根对象；护照号自身的类型和常用输入约束仍在该字段节点编辑。

```json
{
  "if": {
    "properties": { "trip": { "const": "abroad" } },
    "required": ["trip"]
  },
  "then": { "required": ["passport"] }
}
```

编辑条件比较值或添加、删除 `else` 时，「保存规则」先存入抽屉，正文中的「应用到工作台」把已完成的字段和规则一起写成一次草稿修改。取消规则保留打开时的值；离开还有未应用输入时提示处理。页头「保存」负责创建持久修订。修改成功后回到原字段，打开整份 JSON 核对影响，撤销一次恢复原文。

## 实现与验收顺序

1. **基础与原文。** 在对象数组中新增必填整数，删除时同步移除父级必填项，撤销恢复两处。改变显示名称时保留相邻节点的转义、未知关键字和数值 token，保留歧义或语法错误的 JSON 修复入口。
2. **引用及结构。** 切换一个引用，验证本地覆盖和其他使用处保持。删除被引用定义、删除会改变后续 Schema 指针的元组项或替换被引用子树时，检查保护和使用位置。
3. **规则。** 走完整护照号流程，覆盖条件成立、否则分支、依赖、组合、嵌套对象及数组元素，检查取消、应用、撤销、保存重开。
4. **窄窗与只读。** 验证展开、选择、长名称、焦点还原和原 Tab 恢复。只读版本能展开、查看条件和原文，写入入口受版本状态约束。
