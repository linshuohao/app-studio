L1 定义层
设计草稿

基于多端差异、分层复用、复杂上下文校验与内外多级联动，提出可评审的概念模型、组合方式与默认语义。

V0.1 · Proposed聚焦 L1协议表示待收敛2026.10.14
01

定位与能力边界

本草稿保留四层总体架构，专门回答 L1 如何表达复杂动态表单。总体分层与用户给出的能力需求已明确；本草稿的具体抽象和默认语义为 Proposed，用于后续评审，不视为冻结的正式协议。

L1 是可组合的声明式业务定义：描述数据、视图、规则、行为和外部依赖，并允许按场景选择不同组合。
需要表达L1 声明的内容由后续层承担
复杂数据字段、对象、数组、值来源及基础约束数据实例、快照、稳定身份及状态存储
多端视图与行为共享片段、端或场景变体、绑定与操作入口平台组件适配与实际交互执行
复杂计算与校验跨字段依赖、地区策略、领域函数、合法性条件依赖分析、求值与校验执行
多级内外联动触发条件、操作意图、外部输入输出和结果接受策略本地事务、异步调度、结果接受及宿主业务调用
复用和扩展片段接口、组合、版本、函数、物料及能力引用依赖解析、注册、加载和发布治理

L1 不定义 Store 实现、脏队列、事务算法、DOM、任意脚本执行平台和跨系统工作流。正式 JSON 的顶层结构本轮不冻结。

02

核心概念：四类定义与四种共享机制

建议用四类业务定义组织内容，用四种机制建立关联。此处的分类不要求成为八个顶层 JSON 字段，也不要求配置者理解八套语言。

业务定义最小语义典型内容
Data Definition数据是什么，值来自哪里标量、对象、集合、基础约束、默认值或持续计算值
View Definition如何呈现及接收交互容器、控件、步骤、绑定、条件展示和操作入口
Rule Definition哪些关系持续成立，哪些事件导致操作计算规则、约束规则、行为规则
Resource Definition需要什么外部结果能力引用、参数、触发条件、结果契约和失效策略
共享机制职责限制
Reference引用数据、上下文、资源及当前项/父级/根作用域区分定义身份、运行时实例和当前地址；不依赖组件位置
Expression表达纯条件、计算、参数与合法性判断同一表达能力多处使用；不直接修改数据或发起外部操作
Operation表达显式修改或外部操作意图先提供有限操作集，通过 Capability 扩展业务操作
Composition组合片段、参数与场景策略明确导入、导出、版本及覆盖方式，不使用任意深合并

Field、Constraint、Computation 如何定位

Field 是 Data 中可绑定、可引用的数据节点，不另维护一套重复的数据树。对象与数组同样需要可引用的位置；是否所有节点都显式携带 ID，在引用专题中确定。

Constraint 是 Rule 的合法性声明，具有目标、适用条件、检查及错误位置；基础约束留在数据契约，动态约束引用该数据，不重复定义字段结构。

Computation 不独立成为一套语言。表达式加目标绑定构成计算规则，具名表达式提供复用。计算规则明确值的归属，不等同于一次性赋值。

Rule 是概念上的归类；协议可以把相关规则就近内嵌，也可以具名引用。将计算、约束、行为分类，是为了明确语义，暂不决定必须存在统一 rules 目录。

03

分层复用与多端差异

建议组合优先：数据契约、业务规则、交互行为、视图分别成为可复用片段。具体表单选择产品、地区、渠道、终端等上下文，组装成一个可执行定义。复用片段可以有多个，但每个运行时实例仍有明确的数据和状态所有权。

片段复用方式差异示例
数据片段共享业务字段及结构，按显式映射接入不同场景扩展字段或采用不同数据契约版本
业务规则片段共享约束与领域计算，参数化选用策略同一生日字段按不同地区规则判断资格
行为片段共享操作组合，明确引用和写入范围Web 自动查询，移动端确认后查询；前后流程不同
视图片段复用语义绑定，端变体选择布局与物料桌面多列，移动端分步；组件数量与入口可不同

建议的组合契约

  • 片段声明参数、引用需求、公开绑定及写入目标，不读取未声明的其他片段内部对象。
  • 名称进入命名空间，导入绑定显式；外部能力与领域函数固定兼容版本。
  • 按稳定标识显式替换或禁用；追加操作必须声明。冲突不能由加载顺序决定。
  • 提交所需的强制业务约束不可被普通视图或交互变体隐式移除；产品和渠道规则差异以独立策略声明。
  • 静态端变体在准备时选定；地区等会变化的业务上下文成为运行时依赖，变化后相关结果失效。

跨端一致性指共享定义在相同上下文下有相同语义。不同端可以选用不同交互定义，不要求所有端生成同一操作序列。组合来源必须可定位，支持调试和差异检查。

04

计算与分层校验

建议采用基础数据约束 + 动态约束 + 注册领域纯函数 + 可选外部验证。避免将复杂校验全部写入组件，也避免为每一种地区规则增设核心纯函数。

层次内容责任
基础数据约束类型、结构、静态范围及简单格式数据契约描述；具体标准支持范围后续收敛
上下文计算结合日期、地区策略等得到资格年龄或边界表达式调用版本化纯函数；输入、输出和依赖显式
动态约束条件必填、跨字段、集合或产品资格判断约束声明适用条件、谓词和错误关联
外部验证必须访问权威业务服务的资格或身份校验资源引用 Capability；校验结果区分通过、失败、未就绪及异常
生日场景 / 语义示例
输入：生日、出行日期、地区策略、产品规则版本
计算：按选定规则得到资格年龄或允许的生日范围
约束：判断生日是否满足产品资格
结果：关联到生日字段或当前成员，不影响其他成员的错误
依赖变化：重新计算、校验，失效相关报价与外部验证结果

具体地区计算算法作为领域策略实现，不阻塞元模型。领域函数声明签名、版本及确定性；不同端通过相同样例验证。规则上下文与界面语言分开，依赖的日期和地区来源需显式绑定。

约束依赖数据和计算结果，而非依赖错误消息。输入缺失、格式错误或外部未就绪时，下游结果不可用；不得当作成功，也不继续使用旧有效结论。基础与动态约束共同适用，重叠规则避免重复配置，错误使用稳定代码、参数与位置。

05

多级联动与外部影响

Rule 中区分持续派生、合法性检查和事件响应。事件是已发生的事实，Operation 是接下来执行的意图，两者不合并为万能表达式。

联动类型定义方式建议边界
纯派生目标 + 纯表达式一个计算目标只有一个明确值来源；禁止隐藏副作用
内部主动修改触发来源 + 条件 + 有限操作set / clear / reset / 数组增删移动；有序列表有限，不引入任意循环
外部查询资源 + 参数依赖 + 激活/触发策略自动依赖查询或显式触发；结果按相关依赖和作用域判定适用性
外部业务操作显式调用或事件输出 + 输入输出契约保存、更新宿主对象等；明确失败、重试、确认与幂等要求
多级联动 / 业务意图
用户修改出行日期
  → 重算当前成员资格
  → 更新校验状态与报价激活条件
  → 旧报价失效，按策略重新查询
  → 接受仍适用的报价结果
  → 发送明确的宿主通知，或等待用户确认后执行业务操作

操作意图必须限定写入范围及引用上下文。内部联动可以多级传播，但不应通过字段订阅回调形成隐藏逻辑；循环和同目标多写入需要被诊断。

宿主数据经输入上下文、查询或显式更新契约进入；外部返回经受控操作修改表单，不能直接持有内部可变状态。跨表单联动由宿主建立目标实例与通信关系，L1 声明接口，不让表单定义任意寻址其他运行实例。

本地提交稳定后才发出依赖该结果的外部效果。外部成功不可通过本地回滚撤销。需要长流程恢复和跨系统补偿的操作由宿主能力承接。

06

先采用的默认语义

以下作为草稿默认值，后续可依据实际需要增加显式策略；不要求逐项由业务方决定。

事项默认语义
初始化与回填默认值只补缺失数据，不覆盖已提供值。计算、约束和资源建立初始状态；回填不冒充用户输入触发清空链。需要初始化行为时单独声明。
变化触发同值赋值不产生值变化事件；用户输入、宿主批量赋值、回填与资源结果有明确来源，规则显式选择来源。
计算值持续计算的目标默认不可由用户直接写入；允许覆盖需要明确切换值来源，不能依靠最后写入者获胜。
空值缺失、null、空字符串、空集合区分；组件空输入按字段契约规范化，不由每端自行决定。
隐藏与禁用展示状态本身不清空数据、不取消业务约束、不排除提交；这些效果需要分别声明。
异步结果相关输入、目标修改版本或数组实例失效后不接受旧写入；表单其他无关变化不自动使结果失效。
校验与提交强制约束未通过或未就绪时不能正式提交；保存草稿可采用不同门槛。外部异常不等同于合法或非法。
版本实例固定发布版本及依赖版本；业务上下文变化选择该发布范围内的策略，规则升级由明确迁移处理。

这些是 L1 需要表达的语义契约；具体如何识别版本、稳定传播和提交通知，由 L2 / L3 详细设计。

07

仍需权衡的技术选择

这些问题由设计工作继续比较，不作为业务方必须回答的清单。下面给出默认推进方向和验证依据。

选择当前倾向关键权衡与下一步
表达式字符串 / AST规范语义采用受限纯函数与类型；表示先不冻结对照手写成本、设计器编辑、错误定位、跨端解析；用同样例比较字符串与结构化表示。
绑定与引用身份稳定定义身份 + 显式作用域，路径用于数据映射评估所有节点 ID 的配置量与重命名成本；验证数组移动和嵌套片段组合。
规则组织与复用粒度近场简单规则内嵌，复杂规则可具名引用比较就近可读性与跨片段复用；避免一字段多个目录来回跳转，也避免规则藏进视图。
组合与覆盖具名组合、显式替换和冲突诊断先限制通用深继承；验证端、产品和地区叠加时可解释性，随后确定优先级及禁用权限。
数据约束与校验标准基础数据契约与动态约束分工选择支持子集、错误统一及扩展契约；不同时维护两套基础约束。
简化 / 规范两种表示先形成一种完整规范语义，再按常用场景提供简写只有可确定展开且能映射诊断时才提供简化层；不默认承诺无损反向还原。
MVL 或其他顶层结构保持候选用数据、视图、规则和资源关系验证配置成本后再定；名称不决定能力。
行为组合规模有限操作列表 + 资源 + 显式宿主调用验证多级清空、赋值与请求是否足够；不要提前加入通用工作流和任意脚本。

建议优先验证“组合与覆盖”“引用与作用域”“行为组合规模”，它们会直接决定元模型。表达式的具体表示与顶层目录可稍后确定。

08

补充资料与验证路径

当前信息足以继续设计，不存在必须先补齐才能推进的业务问题。需要补充的是用于验证和实现的资料，而非让业务方逐项指定技术方案。

资料用途是否阻塞本草稿
一份代表性复杂表单或字段规则清单检验片段边界、配置量、多级联动与错误关联不阻塞；现有生日与出行日期、动态被保人、报价场景可先验证
一组真实多端差异实例确认哪些复用视图、哪些复用行为、哪些是场景业务策略不阻塞模型；实际交付具体端变体前需要
地区生日/年龄规则及输入输出样例实现版本化领域函数，覆盖临界日期、缺失及异常输入不阻塞 L1 架构；实现该规则和验收前需要
宿主能力的输入输出、成功失败与副作用说明落实资源和业务操作契约，确认单向通知与双向数据交互不阻塞内部模型；集成具体能力前需要

下一步产物

  1. 用两份端变体组装同一个被保人表单，验证共享数据、规则与不同交互可以独立复用。
  2. 展开“出行日期 → 地区计算 → 生日约束 → 报价 → 宿主更新”，标明每个节点的依赖、输出和写入权。
  3. 形成最小元模型：各定义的必要属性、引用与组合接口；先使用语义示例，不冻结 JSON。
  4. 再比较协议表示，用样例反查 L2 可分析性、L3 可执行性与跨端一致性。
本轮评审重点

评审四类定义与四种机制是否覆盖需求，分层组合是否清晰，默认语义是否足以避免歧义。地区算法、字段文案和每个端的具体布局在相应实现阶段补齐。
