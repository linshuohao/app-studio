02

执行摘要：现在真正确定了什么

总体四层架构维持不变；L1 的核心共识是数据与多端视图分离，并采用分层约束模型。前六组已阶段归档。第三组核心只新增 Command 与同步 Reaction；外部请求移交 Host。第四组确认 Material 组合、有限交互连接与默认实时编辑；第五组确认外部校验义务、被动五态与 Readiness；第六组已完成协议架构收敛与原理组合验收；下一阶段先补齐 Material Validation Metadata，再定稿 Canonical Schema。
已确认：数据与视图

同一份业务数据可以被不同终端以完全不同的结构展现。PC 平铺，移动端摘要卡片加详情弹窗。共享业务状态与校验规则。

已确认：约束的组合模型

JSON Schema 处理适合它的基础结构与校验；独立 Constraint 负责复杂跨字段和计算型约束；可复用规则资产按需演进。统一校验结果。

原则确定：逻辑抽象

Expression 是共享的纯计算语言；不再把 Computation 作为平级核心领域。纯派生、同步约束、Command / Reaction 分清；外部请求及状态归 Host。

未定稿：最终协议

data/views/behavior/constraints 是当前方便讨论的候选组织方式，尚未确定字段名称、协议嵌套和所有操作约定。

一句话判断

现在不需要重新设计四层架构，也不需要再回到“万能 MVL 规则”。前六组已阶段归档；第五组已归档，第六组已归档；下一阶段优先补齐 Material Contract + Validation Metadata，再形成最终 Schema。资源查询、上传、外部校验执行和提交流程由 Host 管理，不再建设核心 Resource / Capability 引擎。

03

架构基线：四层不变，宿主边界按第三组收敛

L1 Definition → L2 Preparation → L3 Runtime → L4 Renderer 保持不变。第三组 ADR-03-00 修订的是内部职责：Runtime 不再拥有外部请求、缓存或 Resource Store；Material 与Pure Function 提供受控扩展，Host / View Adapter 自主管理外部 I/O。

层 / 角色当前职责明确不负责

L2Slot 规范化、引用/类型检查、表达式依赖、潜在循环与成本诊断用户数据写入及发起网络请求
L3唯一 Work Data、Typed Read、纯求值、同步约束、数据修改、同步联动、被动外部校验事实与 Readiness网络请求、重试、网络缓存、上传及外部工作流
L4 / Material多 View、绑定、UI Intent、焦点和局部 UI 状态；经 Command 修改数据另立业务数据真值或同步规则
Host / View DataSource Adapter远程选项、SDK/HTTP、异步校验、上传、提交、应用级副作用和有效性检查绕过 Command 直接写 Work Data

远程业务仍可作为完整产品能力，只是不进入表单核心。外部数据供显示时由适配器提供；需要改变 Work Data 时由 Host 明确发出 Command。第五组确认被动校验义务、状态与 Readiness，不等于 Resource 生命周期引擎。

04

产品边界与当前 L1 能力覆盖

产品定位仍为复杂动态表单与结构化数据交互引擎。表单内同步确定性行为属于核心；应用级副作用属于 Host。

能力当前归属
数据与多端视图共享 Data、多份 View Profile、统一 Reference / Scope / Binding；继承第一组。
纯计算与同步约束共享 JSON AST、受控 Slot、Pure Function、Named Expression 和统一同步诊断；继承第二组。
数据修改与联动只新增受控 Command + 同步 Reaction；不是通用 Event / Action 语言。
远程数据与异步校验执行Host / View Adapter 请求并管理 Loading / Error / Retry / Cache；非核心 Resource。
外部校验事实第五组确认义务注册、被动五态、Issues、有效性与 Readiness；接口细节后议。
生命周期与局部编辑第五组 F3/F4/F5 已确认，F6 原则确认；F1/F2 推荐保留，真正 Draft/Undo 需明确需求另评审。

可复用不等于必须成为独立顶层 DSL；核心扩展只允许Pure Function，不建立通用外部 Capability Registry。

05

已定稿 ADR：Data 与多端 View 必须分离

已定稿 一份 Data Definition 支持多份 View Definition。它们可具有不同的层级结构、节点组成和交互路径，并共享同一份业务数据、业务校验和可复用的业务行为。

每端的 Renderer 组件树可以不同；数据契约和校验真相仍应一致。
已确认背后的理由
Data 不等于 Field 组件一个数据字段可以被多个 ViewNode 展示；一个复合控件也可能读写多个字段。
View 不是业务数据的权威来源卡片摘要、详情弹窗、确认页应引用同一个数据模型。
多端视图可完全不同移动端弹窗编辑与 PC 平铺输入是不同交互结构，而不是单纯调整 CSS。
View 不决定业务合法性弹窗未挂载、字段未显示，都不应默认取消其数据约束。

06

已定稿 ADR：Constraint 三层组合

已定稿 在三种方案对比后，最终选定的是A+B+C 的递进式组合，并非三套独立的校验引擎。

A · Data Schema

标准类型、结构、范围、枚举、固定必填及 JSON Schema 原生可表达的条件规则；format 的断言行为由所选校验器策略明确。

B · Form Constraints

复杂跨字段、计算型、上下文相关合法性断言；直接属于当前表单定义。

C · Rule Assets（可选）

复用频率足够高时，将稳定的约束规则参数化、版本化并发布供多表单使用。

一种校验结果，而不是三份彼此竞争的真相
Data Schema / Standard Validator基础结构和原生规则
Form Constraint / Rule Asset纯表达式与领域纯函数；外部校验执行归 Host
↓
Unified Validation Results规则 ID · 数据目标 · 状态 · 错误码 · 可供不同 View 定位
候选方案优势代价 / 边界决定
全放 Data / JSON Schema简单集中，成熟生态跨字段复杂纯函数需要非标准 Keyword，Data 容易膨胀仅保留标准基础与原生条件
独立 Form Constraint复杂断言、引用、增量检查更自然要处理两种规则来源的协调复杂约束的主要归属
共享 Rule Asset跨表单复用、参数化、独立版本治理Registry、发布和调试成本高按实际复用需求增加，不作为初始强制

示例：跨字段年龄限制

用户提出的典型问题：根据出生日期、出行日期和适用地区的年龄计算政策，判断年龄是否符合上限。标准 JSON Schema 不天然包含任意领域日期计算能力，因此补充独立 Constraint。

注意：示例沿用第一组类型化 Reference 与第二组版本化Pure Function 的方向；精确 JSON 标签仍未冻结。缺失输入和求值失败的消费规则继续细化；异步权威校验由 Host 执行，不属于该同步断言。

第二组补充：C1 的同步统一断言、C2 的执行/展示策略分离为方向认可；C3 的按需资产化为原则确认，精确执行契约继续细化。见 C1–C3 明细。

同时确定的语义边界

  • 约束的结果是合法性判断，不是主动状态修改。
  • 编辑过程允许合理的不完整或不合法中间态；Validation Constraint 不等于必须始终成立的 Runtime Invariant。
  • 一个复杂断言可能依赖多个字段，target 只是错误定位，并非完整依赖列表。
  • 约束来源可以有多个，但业务约束应避免在 Schema 和 Form Constraint 中重复维护；结果统一归一化。
  • 隐藏字段不自动清空、不自动跳过校验，也不自动从提交载荷中剔除；需明确策略。
  • 业务权威校验由服务端保证，客户端即时校验不能替代它。
仍需注意

Constraint 在领域语义上独立已经确认；它在协议里最终是顶层 constraints，还是作为其他容器下的独立节点，尚未定稿。不要把最终 JSON 组织误认为已确定。

07

当前 Expression：纯 AST 与递归 ValueSpec

第二组 E1–E7 方向沿用，第六组 P3 明确替代“每个深层 Prop 独立动态许可”的候选方案；实际实现仍由 L2 准备、L3 求值。

Expression 仍为纯 JSON AST。Expression-only 位置（assert/when）可直接 AST；Material props、Command value 等声明为 ValueSpec 的位置，在嵌套任意深度递归识别显式 $expr。静态对象确有保留形状时使用 $literal 或等价显式转义，精确语法未冻结。

不按 op/args 的对象形状猜测，不扫描 Data Schema default、Work Data 或任意外部原始 JSON。Material ID、规则 ID、引用目标等结构字段仍静态；递归 ValueSpec 不等于动态结构编程。Manifest 属性 Schema 用于值类型检查，不再为每个深层 Prop 维护动态白名单。

全局 Named Expression 不隐式捕获调用者局部 Scope；局部逻辑优先内联。命名 DAG、有限聚合、Pure Function、静态/运行成本保护继续沿用，不恢复参数化通用函数与任意脚本。

严格 Typed Read、错误传播与不使用旧值保持；逐纯函数传播、Literal 精确转义与预算阈值仍待最终规范。详见 递归动态值。

08

第三组归档：Command + 同步 Reaction

前两组的 Expression、Constraint、Reference、Scope 直接复用。第三组不是新的工作流系统，当前决策明细见 第三组归档 V0.1。

编号阶段性边界状态
ADR-03-00内部同步数据事务、纯计算与约束；外部 I/O 归 Host已确认
B1Set/Replace、Patch、Remove、数组与 Batch 等受控数据修改原则确认
B2Reaction：多 watch + 可选 when + 同步 then原则确认
B3以实际 Data Change 触发；View Intent 不并入通用事件总线原则确认
B4when 为纯 Expression，Command value 为受控动态槽位原则确认
B5Command 与 Change 不要求 1:1，对象修改可影响多个引用已确认
B6稳定发布；执行失败不发布部分成功，校验无效不等于执行失败原则确认
B7确定顺序、同目标后写覆盖；不引入 priority / 冲突仲裁 DSL原则确认
B8复用类型化引用、词法 Scope 和 Runtime 稳定身份已确认

监听与条件分开

多个 watch 中任意实际变化使 Reaction 成为触发候选（OR）；when 读取当前数据作纯判断，其引用不自动追加为 watch。then 只产生同步数据 Command，不能访问 HTTP、SDK 或外部异步能力。watch 和 target 不使用任意表达式拼接路径。

覆盖与事务

一个对象 Command 可以影响多个变化引用。同目标同步写入按确定顺序后写覆盖，不默认报错，不强制 priority。声明顺序、级联跨轮顺序、去重、相等性、循环与预算的精确规则仍待 L2/L3；不等于无顺序要求或无限联动。

执行非法或不终止不能发布部分成功；业务 invalid 和 Parse Failure 仍允许作为编辑工作态。纯派生默认不写回，仅确需持久修改时通过 Command 的动态 value 显式写入。语法与算法未冻结。

09

当前数据与引用基础：继承第一组，按第六组统一 Scope

D1–D6 采用、D7 原则保持；第六组进一步明确 Binder、引用和实例身份的职责，而非新增全局 Scope Store。

根路径简写始终指向 Form Data Root，不因位于 Repeater 自动改变含义；局部数据显式指定 scope。JSON Pointer 的空字符串为根，"/" 是空名称属性，~1/~0 保持标准转义含义。

View ScopeNode、Constraint/Reaction 入口用同一 ScopeBinder：from + as + mode（one 默认、each 集合）。Binder 可以是一条有序词法链；from 必须是 DataReference，不由任意 Expression 动态生成，也不自动创建不存在的对象/数组。

one 绑定对象或确定位置，each 在 View 实例化子树，在规则中逐项适用。L2 维护词法绑定；L3 统一解析数据位置、稳定项身份和删除失效。View 与规则各自有词法帧，但不产生两套业务实例身份；不建全局 Scope Registry。

Data Reference 取得值，ScopeHandle 定位当前实例；数据相等不代表同一实例。事件环境包含受控 Payload（source:event）与捕获的 Scope；Handle 不是可直接发给外部服务的业务 ID。别名遮蔽、最终 Handle/替换语法仍待 Schema 与 L3 细化。

既有方向现行接口边界
Data / ValueJSON Schema + 最小扩展；唯一可写 Work Data；ParseResult 仅成功/失败，Missing/null/业务 invalid 分开。

当前 View：Material / ScopeNode / TemplateUse

第四组多端独立、默认 Live Edit 与 Material 方向保持；第六组明确移出核心 Presentation，并统一结构引用。

ViewNode 收敛为 MaterialNode、结构性 ScopeNode 与 TemplateUse。容器、布局和复合业务组件都是 Material；Material 通过 trigger/content 等 Slots 自主管理开闭、焦点、动画与 UI State，Slot 名称本身不自动赋予点击行为。

Profile 使用 entry；需要复用或独立引用时定义 Named View Template 并静态 $use，不再另建 root/targets/fragments 多套内容目录。模板参数显式接收 ScopeHandle，不隐式捕获外部局部变量；共享定义不共享组件实例和 UI State，也不复制业务数据。

Binding 只关联数据，默认端口与具名端口沿用同一模型；具体绑定字段名仍候选。children 建议作为 slots.default 的 Authoring 简写，同一节点不能同时给两者。Manifest 声明 Props 类型、Binding/Slot/Event 端口；Material Validation Metadata 的消费契约仍是明确缺口。

核心 view.present / view.dismiss 与独立 Presentation Spec 已移出。Interaction 仅保留 form.command、host.emit 的受限连接；普通字段修改走 Binding Adapter，不额外重复声明写入事件。跨树 UI 协作先用复合容器或 Host，不恢复核心 UI Action Engine。

Profile Bundle 只裁剪无关 View/Template/依赖，不能因 UI 未显示而删除共享 Schema、Constraint、Reaction 或必需外部校验义务。当前组合示例仅原理验收，不表示代码已通过端到端测试。

依据：ViewNode、Named Template、容器物料。

第五组归档：Form Lifecycle / Validation / Submission

本组最重要的新增不是生命周期 DSL，而是可靠判断已知校验完整性的实例契约。F1–F6 原始状态矩阵 明确保留 F1/F2 推荐，不能伪造成全部已定稿。

编号当前结论状态
F1静态默认值 + Host 初始数据，Missing 补缺；显式 null 不覆盖推荐保留
F2区分 Update / Reinitialize / Reset；Reset 默认恢复最近初始化基准推荐保留
F3默认 Live Editing，不为 Modal 默认新建 Draft Store已确认
F4-A解析失败影响依赖求值；业务 Constraint 失败不全局阻断 Reaction已确认

F4-CRuntime 被动登记五态和有效性；依赖变化使旧结论失效已确认（语义）
F4-D外部校验不自动暂停/恢复/触发同步 Reaction；异步后续修改由 Host 发 Command已确认

F6实例能力与正交状态契约；不建通用 Lifecycle / Submit Workflow DSL原则确认

义务、状态、有效性

Definition 声明固有外部校验 ID、依赖、目标、适用条件和是否必需；Host 可补充环境义务，正式 Readiness 判断前应完成必需注册，同 ID/Scope 不能静默覆盖。Runtime 被动登记 Unverified / Pending / Valid / Invalid / Error、Issues 及结论有效性，Host 管理请求、防抖、超时、重试和提交。

五态不是五种 ParseResult：值解析仍只有成功/失败。适用性为独立维度，不能将无法判定的必需项当作通过；issues=[] 不证明已验证。对每项必需校验，只有适用于当前依赖的 Valid 结论才满足 Readiness。

结论要区分实例、规则、Scope、依赖状态及一次调用；依赖变化或 Host 主动失效后，不接受旧结果，包括 alice→bob→alice 的 ABA 情形；无关字段变化不应自动失效。具体 token、索引与 API 均未冻结。

Readiness 与提交

Runtime Ready 仅证明当前已声明/注册、适用且必需的内部和外部校验满足：当前工作值可生成符合契约的输出，同步约束通过，必需外部项全为当前有效 Valid，且报告/输出/义务目录对应一致状态。未知适用性、Unverified、Pending、Invalid 或 Error 的必需项都不能放行。

Host 仍决定权限、业务条件与真实提交，并在异步等待后复核当前报告和输出。Ready 不等于服务端批准、HTTP 成功或业务提交许可；Runtime 不发网络请求，也不以校验状态自动挂起/恢复 Reaction。

生命周期推荐与剩余接口

F1/F2 推荐静态默认值与 Host 值合成、Update 正常联动、Reinitialize 重建基准、Reset 恢复最近初始化基准且不默认重放字段编辑。D7 的回填优先/Missing 补缺原则保持；对象/数组细则、生命周期 API、触发、基准与缓存实现仍未冻结。

第三组数据 Set/Replace Command 仍是普通同步修改；F2 实例 Reinitialize/Replace 中 Replace 仅候选命名，不能混同。基准快照是不可编辑参考，不是第二份可写业务真值。切换 Profile 且沿用同实例不重初始化、不重放输入或隐式触发 Reaction，裁剪不移除校验义务。

完整边界见 遗留接口，下一组进入统一 Protocol。
