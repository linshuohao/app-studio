01

结论概览与归档口径

本文件归档L1 第四组 View / View Profile / Material / Interaction 的讨论与阶段性决策。它接续第一组 Data / Reference / Scope / Binding、第二组 Expression / Pure Function / Constraint、第三组 Behavior / Reaction / Command，并严格限制在 View Definition 的职责和可声明语义，不提前设计 L4 组件内部实现或 L3 调度机制。

一句话结论

一份 Form Data 对应多份独立 View Profile；视图以 Material 组合为主，复用统一 Binding 与 Expression；Material 负责内部交互，必要时通过受限 Event → form.command / host.emit 连接数据操作或宿主；容器 Material 自主管理视图呈现。移动端详情默认实时编辑同一份 Runtime Data。

03

继承前三组的不可破坏约束

既有结论第四组必须遵守的结果
Data 与 View 独立View 可以完全不同，但不能各自拥有权威业务数据
单一 Form Working DataModal、Card、PC Input 共享相同状态来源
类型化 Reference + Scope所有数据绑定和动态重复项沿用统一寻址规则
Binding 支持基础与复合关联普通输入简写、复合物料支持多个具名数据端口
Expression 纯计算、Dynamic Slot 受控物料属性需显式声明哪些位置允许表达式
Constraint 独立于 View错误按规则 / 数据引用 / Scope 归属，不绑定 UI 节点
Command 是数据修改唯一受控入口交互和物料不得绕过 Runtime 直接篡改 Work Data
Reaction 监听 Data 变化View 内不同点击行为不能复制或替代共享业务联动
外部请求由 Host 执行Material 可以调用宿主适配能力；Form Engine 不建立 Query Workflow

以上是本组设计的约束条件，不代表第四组需要重新设计这些公共基础抽象。

07

V2 当前 ViewNode：MaterialNode / ScopeNode / TemplateUse

第六组把对象绑定与集合重复统一为结构性 ScopeNode；默认是 Material 组合，容器也属于 Material，不再新增独立 repeat 或完整 UI 节点分类。

候选语义示例，字段尚未冻结
{
  "scope": {
    "from": "/contacts",
    "as": "contact",
    "mode": "each"
  },
  "node": {
    "material": "contact-card",
    "bind": {
      "source": "data",
      "scope": "contact",
      "path": ""
    }
  }
}

MaterialNode 组织 Props、数据 Binding、Children/Slots 和受限 on；ScopeNode 用 from/as/mode 引入词法绑定；TemplateUse 用静态 $use 复用内容。对象 mode:one、集合 mode:each 同一模型，身份由 L3 统一。字段名、ID、Slot 类型和参数格式仍未冻结。

Manifest 定义 Material Props 的类型、具名 Binding Port、Slot 基数和必要 Event Payload；平台组件负责内部 UI。Props 按递归 ValueSpec 求值和类型检查，不在每个属性上增加 dynamic:true 开关。

    "contact": {

尚有能力缺口：输入组件、对象摘要与数组卡片如何按 DataReference / Scope 消费 Validation Metadata（Issues、状态、汇总）尚需明确，不能仅靠 Props/Binding 表就宣称完整支持校验呈现。

09

V4 · Binding 只做数据关联

设计纠偏

协议不需要为每个字段反复配置 read / write 或自动生成双向映射。Binding 负责“这个节点关联哪一份数据”，能否编辑以及怎样提交变化由 Material Adapter 的能力决定。

编辑组件
编辑仍用普通 Binding
{
  "material": "text-input",
  "bind": "/user/name"
}
只读展示
无需另建 ReadOnlyBinding
{
  "material": "text",
  "bind": "/user/name"
}

如果同一 Input 的编辑能力受当前条件限制，使用已允许的动态物料属性，例如 readonly / disabled；但 UI 只读不等于业务权限控制。

复合控件仍可引用多个数据槽位：例如 DateRange 的 start 与 end。它的值更新方式来自 Material Adapter 契约，不需要在 Definition 中定义可逆的通用转换表达式。

复合 Binding · 候选示例
{
  "material": "date-range",
  "bind": {
    "start": "/period/startDate",
    "end": "/period/endDate"
  }
}

数据发生修改时，不管 UI 来自 PC、移动 Modal 或外部 Host，最终都应进入第三组受控的 Command 接口。

10

V5 修订：容器呈现内聚，保留必要数据/宿主连接

组件内部交互留给 Material。第四组曾用跨节点 view.present 连接弹层，第六组因容器/实例/UI Action 调度成本将其移出核心，当前用容器 Material 的 trigger/content Slots 自主管理开闭。

普通字段变更由 Binding Adapter 完成；按钮修改数据可映射已有 form.command，业务信号可映射 host.emit。跨树 UI 协作优先复合容器或 Host，不新增 Presentation Engine。

V5 当前有限 Event → Intent：form.command / host.emit

意图执行方边界
form.commandRuntime仅调用封闭数据 Command，不重复字段 Binding 的普通写入。
host.emitHost有类型与授权的业务通知，不在 Definition 编排 RPC。

{

  "props": {
    "label": "添加联系人"
  },
  "on": {
    "activate": {
      "type": "form.command",
      "command": {
        "op": "array.insert",
        "target": "/contacts",
        "value": {
          "name": ""
        }
      }
    }
  }
}

Interaction 仅在临时事件环境读取 source:event 及捕获的 Scope；事件 Payload 与业务数据/ScopeHandle 不混同。精确参数与访问规则仍待 Schema。

12

统一 ScopeBinder 与当前项 Handle

根路径简写始终指向 Form Data Root，不因位于 Repeater 自动改变含义；局部数据显式指定 scope。JSON Pointer 的空字符串为根，"/" 是空名称属性，~1/~0 保持标准转义含义。

View ScopeNode、Constraint/Reaction 入口用同一 ScopeBinder：from + as + mode（one 默认、each 集合）。Binder 可以是一条有序词法链；from 必须是 DataReference，不由任意 Expression 动态生成，也不自动创建不存在的对象/数组。

one 绑定对象或确定位置，each 在 View 实例化子树，在规则中逐项适用。L2 维护词法绑定；L3 统一解析数据位置、稳定项身份和删除失效。View 与规则各自有词法帧，但不产生两套业务实例身份；不建全局 Scope Registry。

Data Reference 取得值，ScopeHandle 定位当前实例；数据相等不代表同一实例。事件环境包含受控 Payload（source:event）与捕获的 Scope；Handle 不是可直接发给外部服务的业务 ID。别名遮蔽、最终 Handle/替换语法仍待 Schema 与 L3 细化。

组合语义示例，非冻结协议
{
  "scope": {
    "from": "/contacts",
    "as": "contact",
    "mode": "each"
  },
  "node": {
    "material": "contact-card",
    "bind": {
      "source": "data",
      "scope": "contact",
      "path": ""
    },
    "on": {
      "remove": {
        "type": "form.command",
        "command": {
          "op": "array.remove",
          "target": "/contacts",
          "item": {
            "$scope": "contact"
          }
        }
      }
    }
  }
}

ScopeNode each 实例化 View；规则可独立使用同一 Binder。表达式、普通 Props 和 Command 只能使用已有绑定，不能任意声明全局 Scope。

V6 当前复用：Named Template + 静态 $use

第六组将原 Fragment/root/targets 收敛为 Profile entry + Named Template + TemplateUse。模板不复制 Work Data、事务或生命周期；引用不创建共享组件实例。

组合语义示例，非冻结协议
{
  "viewTemplates": {
    "contact-fields": {
      "params": {
        "contact": "data-scope"
      },
      "node": {
        "material": "stack",
        "children": [
          {
            "material": "text-input",
            "bind": {
              "source": "data",
              "scope": "contact",
              "path": "/name"
            }
          }
        ]
      }
    }
  },
  "views": {
    "expanded": {
      "entry": {
        "scope": {
          "from": "/contact",
          "as": "contact",
          "mode": "one"
        },
        "node": {
          "$use": "contact-fields",
          "with": {
            "contact": {
              "$scope": "contact"
            }
          }
        }
      }
    }
  }
}

参数为候选语法；模板显式取得 Handle，不隐式捕获调用者局部变量，不做动态 DOM 替换，不允许无限递归。L2 解析模板与检查环/类型。

显隐、禁用与校验的关系

View 的展示条件只控制可见性和 UI 交互，并不自动修改 Form Data，也不自动改变 Constraint 的业务合法性。

受控 Dynamic Slot · 示例
{
  "material": "text-input",
  "bind": "/companyName",
  "props": {
    "visible": {
      "$expr": {
        "op": "eq",
        "args": [
          {
            "ref": "/accountType"
          },
          "business"
        ]
      }
    }
  }
}
需求明确归属
根据字段值显示或隐藏组件View Dynamic Slot + Expression
隐藏时清空 companyName需要数据联动时显式用 Reaction
隐藏时不校验 companyName需要适用条件时显式用 Constraint.when
禁用 InputMaterial/UI 属性；不是权限或数据删除
同一错误在 PC 字段与手机卡片呈现Validation Issue 绑定数据引用；View 负责呈现方式

不能因为 Compact Profile 没有展示某字段，就使该字段的共享业务约束或数据值失效。

被否决或明显降级的方案

候选决定原因
所有 Profile 共享一棵树并动态重组不采纳结构差异会引入大量条件和转换规则
View Inheritance + Node Override不采纳配置合并、冲突和升级治理成本高
为所有 UI 元素建立专用 Node 类型不采纳演变为通用页面搭建 DSL
Binding 配置 read / write 逆向映射 DSL不采纳组件输入契约与数据关联混淆
完全禁止声明式 Interaction已修订跨组件连接会重新进入专用物料或宿主代码
完整 View Interaction 工作流不采纳会引入异步操作、条件分支、动作链和页面生成职责
Modal 默认有独立 Draft Data不采纳与默认实时编辑及唯一权威 Work Data 不符
View 隐藏字段即清空数据不采纳破坏 Data / View 独立与共享校验语义
Form Engine 负责请求远程选项不纳入核心资源获取属于 Host / Material Adapter

尤其应当保留的历史修订

V5 不是从“完全不需要”直接变成“完整 DSL 很重要”；实际结论是：内部交互仍属于物料，只有组件边界之外的明确连接关系值得声明。因此保留有限 Event → Intent，而不是全面恢复事件编排。

L1 / L2 / L3 / L4 / Host 职责交接

层次本轮应明确的责任不应该承担的工作

用例验收：第四组足够表达什么？

S1 · 普通 CRUD：TextInput 通过 bind 更新单字段；无需独立 Interaction；校验由共享 Constraint 处理。
S2 · PC 平铺 / Mobile 摘要：独立 Profile 指向同一数据契约；Mobile Card 可打开独立详情。
S3 · 嵌套联系人：Repeater 为每项建立 Scope；Material 的编辑/删除意图正确作用于当前项；移动或删除不误绑新索引。
S4 · 数据依赖显隐：动态槽位表达 visible；隐藏不清空数据、不自动停用共享校验。
S5 · 复合物料：DateRange、Card/Editor 可用具名 Binding Port 与 Slots，不需要附加通用逆向写入 DSL。
S6 · 异步外部数据：远程选项由 Host / Material Adapter 管理；选中值仍交由 Runtime 保存。
S7 · Profile 按需交付：客户端只收到选中视图及必要依赖；不因视图裁剪破坏共享 Data / Constraint / Behavior。
S8 · 编辑弹窗：实时修改直接进入 Work Data、共享联动生效；取消若必须回滚，另列 Editing Context 需求。

这些是后续正式协议和 L2/L4 实现必须通过的场景，不代表已经编写自动化测试。

正式记录：第四组阶段性决策

ADR-04 · 阶段性定稿

View Definition 负责多 Profile 视图组织、Material 组合、统一数据 Binding、受控动态属性和可选的有限 Event → Intent 映射；Renderer 实现内部交互，Host 管理外部副作用。所有表单业务数据以单一 Work Data 为权威，移动端详情编辑默认实时生效。

01

多端视图独立

每个 View Profile 可有完整独立视图树，并支持 Profile 级按需交付。

02

视图结构轻量化

Material 组合为主，只保留 Repeat / Scope 等必要的表单语义。

03

Binding 最小职责

负责关联数据，不复制组件内部读写实现或表达式逆向赋值。

04

内部交互留给组件

Select、Modal 内部开关、焦点等不写入 Form Definition。

05

保留受限交互连接

Material Event 按需映射到已有 Command、内部 View 呈现或受控 Host 意图。

06

局部状态与业务数据分离

View State 属于 Renderer，业务数据进入唯一 Runtime；Modal 默认实时编辑。

07

不拓展为低代码页面系统

不支持任意页面导航、异步编排、通用脚本、完整 UI 继承覆盖体系。

归档状态：第四组 L1 能力边界已收敛；候选 DSL、事件参数、目标引用和交付 API 尚未冻结。
