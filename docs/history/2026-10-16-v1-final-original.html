00 · EXECUTIVE SUMMARY

定稿结论与阅读说明

已收敛
L1 的架构模型可以定稿；本文件是 架构与语义决策定稿，并非已通过机器校验的最终 JSON Schema 发布包。

这份文档整合此前六组专题及后续统一收敛讨论，并按最终有效决策重排：先讲协议、后讲组合，最后归档被否决的方案。历史示例中与最终方案冲突的字段（例如 view.present、bind 作为 Canonical、独立 fragments）均不再视为当前规范。

定位

面向复杂 C 端业务表单的声明式 Definition Protocol，不建设通用应用 DSL。

已定方向

Data / Reference / Scope / Expression / Constraint / Command / Reaction / View / Material / Host 边界。

发布状态

架构已冻结；TS 类型、JSON Schema、兼容规则和机器化验收仍属于协议固化工作。

阅读方法

优先看「总决策表」和「规范示例」；需要了解方案取舍再看「修订史」。

规范声明级别
已冻结：架构或语义已经有明确共识。待固化：方向明确，但特定类型形状、静态检查算法或字面量语法仍应由正式 TS/JSON Schema 对齐。示例中的字段名以本文 V1 候选 Canonical 为准；不能将“架构定稿”误读为所有细节已通过校验。
01 · FOUNDATIONS

设计目标、边界与硬约束

已收敛
  • 唯一业务数据源：一个 Form Instance 只有一份权威 Working Data；视图复用不复制业务数据。
  • 跨端共享业务语义：Data / Rules 不依赖 Web、Flutter、Modal 或 Drawer。
  • 协议只承载稳定语义：复杂视觉与内部交互交由 Material，外部请求与业务流程交由 Host。
  • 可静态分析：引用、表达式和指令受到约束；不接受任意 JS 函数、动态路径拼接和通用工作流。
  • 默认使用成本低：简单表单只应需要 Schema + Material View + Binding；复杂场景按需引入 Scope、Reaction、Template。
L1 应表达不属于 L1 Definition
数据形状、字段引用、作用域数据存储结构、字段状态机具体实现
纯表达式、约束、同步联动、受控指令求值调度、事务与通知算法
物料结构、端口绑定与语义事件映射DOM、Portal、焦点、滚动、局部 UI State
外部校验义务实际 API、网络请求、重试、提交流程

04 · CANONICAL ROOT

唯一 FormDefinition 顶层结构

已收敛
架构定稿 · 顶层字段
interface FormDefinition {
  protocolVersion: string;
  id: string;
  version: string;

  data: { schema: JsonSchema };
  expressions?: Record<string, Expression>;
  constraints?: Constraint[];
  reactions?: Reaction[];
  views: Record<string, ViewProfile>;
  viewTemplates?: Record<string, ViewTemplate>;
  metadata?: Record<string, JsonValue>;
}

业务规则处于 Form Definition 级别，不能因为切换 View Profile 或某字段暂时隐藏就失效。metadata 只用于非执行性元数据，不能通过它绕过已确定的协议语义。

明确不增加的顶层域
actions、behaviors、resources、services、submissionWorkflow、presentation、validationState、scopes 不进入 V1 核心。
05 · REPRESENTATION

Canonical、Authoring、Prepared 的分离

已收敛
形式定位示例
Canonical Protocol唯一正式结构：机器验收与交换bindings.value = {source:"data",path:"/name"}
Authoring Syntax可选的书写简化，不扩展语义bind: "/name"；children: [...]
Prepared RepresentationL2 内部交付产物，非 L1 文档的一部分已解析引用、编译依赖、索引及 Profile 选择

遵循“一种语义，一种 Canonical 形式”。有简写也不能把简写当成第二套协议。跨端传递、规范校验和文档样例均应优先使用 Canonical。

06 · DATA

Data / Value / Default / Output

已收敛
数据结构只定义一次
{
  "data": {
    "schema": {
      "type": "object",
      "properties": {
        "applicant": { "$ref": "#/$defs/Person" },
        "insureds": { "type": "array", "items": { "$ref": "#/$defs/Person" } }
      },
      "$defs": {
        "Person": {
          "type": "object",
          "properties": {
            "name": { "type": "string" },
            "age": { "type": "integer" }
          }
        }
      }
    }
  }
}
  • 数据与视图分离：JSON Schema 管结构与基础约束；单个 Form 不需要按 Profile 创建多份业务 Schema。
  • Working Data 允许暂时不合法：例如输入过程、Host 回填或旧数据，不得静默以“最后一次合法值”替换当前数据。
  • 缺失与 null 不同：Missing、null、解析失败属于不同语义；不设计独立的 Incomplete 解析状态。
  • 默认值：Host 初始化数据优先，Schema 默认值可填充真正缺失的位置；不覆盖显式 null。
  • 提交：通过 Schema、内部约束、必要外部约束和输出转换后才构造规范化输出；Host 负责真正提交。
07 · REFERENCE

Reference：统一寻址规则

已收敛
引用类别
type DataReference = {
  source: 'data';
  path: string;          // JSON Pointer
  scope?: string;        // 仅词法可见的局部名称
};
type ContextReference = {
  source: 'context';
  path: string;
};
type EventReference = {
  source: 'event';
  path: string;
};
不同来源的只读/可写能力由所处位置约束
{ "source": "data", "path": "/applicant/name" }
{ "source": "data", "scope": "insured", "path": "/age" }
{ "source": "context", "path": "/countryOptions" }
{ "source": "event", "path": "/selectedValue" }

统一使用 JSON Pointer："" 表示引用根值，"/" 表示空字符串字段名。绝对路径简写（例如 "/applicant/name"）始终从 Form Data 根开始，不会随当前 Scope 隐式变成相对路径。

位置级约束
Expression 可读取受允许的 Data / Context（Event 仅在交互上下文有效）；Command target 只能写 Data，不能写 Context、Event 或 Material Props。
08 · SCOPE

ScopeBinder：局部词法绑定，不建全局注册表

已收敛
唯一绑定语义
interface ScopeBinder {
  from: DataReference;
  as: string;
  mode?: 'one' | 'each';
}

one 将一个数据位置绑定为局部名称；each 对一个数组的每个项建立独立上下文。在 View 的 ScopeNode 中，each 直接表示重复实例化对应子视图，父 Material 不需要额外 repeat。

View 中的逐项实例化
{
  "scope": {
    "from": { "source": "data", "path": "/insureds" },
    "as": "insured",
    "mode": "each"
  },
  "node": {
    "material": "insured-card",
    "bindings": {
      "value": { "source": "data", "scope": "insured", "path": "" }
    }
  }
}

View、Reaction、Constraint 在协议允许的位置建立局部 Binder；它们不定义独立的数据存储域。L2 处理词法名称绑定，L3 对应实际数据位置与数组项稳定身份；不同规则使用同名别名，不构成全局 Scope 冲突。

不扩张为通用变量系统
Scope 只能出现于明确的结构性入口；普通 Props、Expression 和 Command 都不能随意创建 Scope。from 不接受任意 Expression 拼出的动态数据位置；词法链中不得重复遮蔽已有别名（V1 保守规则）。
09 · ITEM IDENTITY

ScopeHandle 与数组实例身份

已收敛
Data Reference 与 ScopeHandle 不混用
// 获取当前数组项的业务值：
{ "source": "data", "scope": "insured", "path": "" }

// 在需要项身份的命令中表达当前实例：
{ "$scope": "insured" }

// 示例：精确删除当前项，而不是按数组下标删除
{
  "op": "array.remove",
  "target": { "source": "data", "path": "/insureds" },
  "item": { "$scope": "insured" }
}

ScopeHandle 表示数据实例的定位身份，不代表数据副本，也不是业务主键。数组排序后不能悄悄指向新的同下标对象；原实例被删除时句柄失效。普通 View Template 参数则只传 Data Reference，不需要对外暴露 ScopeHandle。

10 · EXPRESSION

Expression AST 与 ValueSpec

已收敛
概念类型 · 正式 Union 仍需消歧校验
type Expression =
  | JsonPrimitive
  | { ref: Reference }
  | { use: string }
  | { op: string; args: Expression[] }
  | { literal: JsonValue };

type ValueSpec =
  | JsonPrimitive
  | { $expr: Expression }
  | { $literal: JsonValue }
  | ValueSpec[]
  | { [key: string]: ValueSpec };

Expression 是纯计算 AST，采用严格类型、有限内置 Pure Function 与版本化领域纯函数。Named Expression 可复用，但全局命名表达式不得隐式捕获调用方的局部 Scope；V1 不引入参数化函数语言。

动态 Expression 可以出现在任意嵌套 ValueSpec 内
{
  "material": "summary-card",
  "props": {
    "title": "投保摘要",
    "badge": {
      "visible": {
        "$expr": {
          "op": "eq",
          "args": [
            { "ref": { "source": "data", "path": "/plan" } },
            "premium"
          ]
        }
      }
    }
  }
}
协议位置表达式形态
constraint.assert / reaction.when / expressions.*直接使用 Expression AST
props.* / command.value / host.emit.payload递归 ValueSpec，通过完整的 $expr 包装进入表达式
需要原样保留标记对象通过显式 Literal 转义表达，不能按普通对象形状误判表达式
求值失败的语义
解析失败或类型不匹配不等于 Expression 返回 false，也不等于自动使用最近一次合法值。同步业务 Constraint 不通过、外部校验 Pending 也不应自动阻断全部 Reaction。
11 · CONSTRAINT

Constraint：内部断言与外部校验义务

已收敛
Internal · 可同步求值的业务约束
{
  "id": "age-eligible",
  "kind": "internal",
  "scope": {
    "from": { "source": "data", "path": "/insureds" },
    "as": "insured",
    "mode": "each"
  },
  "assert": {
    "op": "gte",
    "args": [
      { "ref": { "source": "data", "scope": "insured", "path": "/age" } },
      18
    ]
  },
  "issue": {
    "target": { "source": "data", "scope": "insured", "path": "/age" },
    "code": "AGE_BELOW_MINIMUM"
  }
}
External · 声明义务，不声明 URL 或请求策略
{
  "id": "insured-eligibility",
  "kind": "external",
  "scope": {
    "from": { "source": "data", "path": "/insureds" },
    "as": "insured",
    "mode": "each"
  },
  "dependsOn": [
    { "source": "data", "scope": "insured", "path": "/age" },
    { "source": "data", "scope": "insured", "path": "/idNumber" }
  ],
  "target": { "source": "data", "scope": "insured", "path": "/idNumber" },
  "requiredForSubmit": true
}

内部约束使用可选 when 和必需的 assert；外部约束声明依赖、归属位置及是否阻断提交。Constraint 不执行 Command，不设计 onFail 动作链。

12 · VALIDATION

校验状态与提交 Readiness 的协议边界

已收敛

L1 只需要完整声明约束；各约束实例的结果、失效和状态迁移由 L3 统一管理，不是一个需要写入 Form Definition 的 validationState 字段。外部校验由 Host 执行并上报，而不是由 Form Runtime 自行发送网络请求。

状态语义
unverified尚未对当前有效数据版本取得结论
pending对应校验正在进行
valid当前有效输入版本验证通过
invalid当前有效输入版本验证未通过
error校验执行错误，不能被当成通过

一个外部 Constraint 在数组 Scope 下会派生出多个实例义务；结果需与具体数据项及版本关联。数据发生依赖变化后旧结果失效。Submit Readiness 依赖 Schema、内部约束、输出有效性及所有当前适用且 requiredForSubmit 的外部约束，不能以“未知或请求失败”冒充通过。

与 View 的关系已经定稿
View 的 bindings 只写数据位置。无需 validationBind、errorBind 或物料校验管理字段；Runtime 提供状态，Material 只负责显示。字段状态机的具体结构留到 L3。
13 · COMMAND

Command：封闭的受控数据修改语言

已收敛
操作语义边界
set替换目标 Data 值目标必须为可写 Data Reference
patch浅层对象字段更新不隐式递归深度合并
remove删除属性位置区分将属性设为 null
array.insert插入集合项受目标 Schema 约束
array.remove按稳定项身份删除不可仅依赖不稳定 index
array.move按稳定项身份移动保留被移动项身份
batch把多个 Command 视为一次逻辑提交不能变成通用工作流
修改目标与计算值必须严格区分
{
  "op": "set",
  "target": { "source": "data", "path": "/order/total" },
  "value": {
    "$expr": {
      "op": "mul",
      "args": [
        { "ref": { "source": "data", "path": "/order/price" } },
        { "ref": { "source": "data", "path": "/order/quantity" } }
      ]
    }
  }
}

Command 只做表单数据修改。请求上传、业务审批、支付、弹窗动画和远端提交均不变成 Command 类型。复杂业务逻辑可以由 Host 根据结果发回一个受控 Command。

14 · REACTION

Reaction：明确触发与条件的边界

已收敛
规则级作用域可使用有序绑定链
interface Reaction {
  id: string;
  scope?: ScopeBinder | ScopeBinder[];
  watch: DataReference[];
  when?: Expression;
  then: Command[];
}
数据变化时的最小联动声明
{
  "id": "clear-city-on-country-change",
  "scope": {
    "from": { "source": "data", "path": "/insureds" },
    "as": "insured",
    "mode": "each"
  },
  "watch": [
    { "source": "data", "scope": "insured", "path": "/country" }
  ],
  "then": [
    {
      "op": "set",
      "target": { "source": "data", "scope": "insured", "path": "/city" },
      "value": null
    }
  ]
}

watch 决定何时触发，when 决定触发后是否执行；二者不能互相代替。Expression 读取到的依赖不应自动变成触发条件。then 已经是有序 Command 数组，不必再强制包一层 batch。

范围约束
Reaction 只消费内部同步 Data Change；外部异步校验完成并不会自动重新触发所有联动。需要改变数据时由 Host 显式提交 Command。
15 · VIEW

View：Profile 与三种结构节点

已收敛
V1 结构形态
type ViewNode = MaterialNode | ScopeNode | TemplateUse;

interface ViewProfile {
  entry: ViewNode;
}

interface MaterialNode {
  material: string;
  props?: Record<string, ValueSpec>;
  bindings?: Record<string, DataReference>;
  slots?: Record<string, ViewNode[]>;
  on?: Record<string, InteractionIntent>;
}

interface ScopeNode {
  scope: ScopeBinder;
  node: ViewNode;
}

interface TemplateUse {
  $use: string;
  with?: Record<string, DataReference>;
}

View Profile 是不同场景的入口选择，不是不同业务数据源。PC 可以平铺编辑；移动端可以使用卡片和底部弹层。是否渲染列表，由 ScopeNode mode: each 决定，不额外声明 Repeat。

$use 是对命名视图结构的静态复用，不是 DOM 替换命令，不共享 UI 组件实例，更不是子表单。是否 Portal / Teleport、何时展开、动画如何实现均由容器 Material 自行决定。

16 · BINDING

Binding：唯一 Canonical 是具名端口映射

已收敛
Material Port → Data Reference
{
  "material": "date-range",
  "bindings": {
    "start": { "source": "data", "path": "/travel/startDate" },
    "end": { "source": "data", "path": "/travel/endDate" }
  }
}

Canonical 永远使用 bindings: Record<PortName, DataReference>。bind: "/name" 仅是 Authoring 简写；没有 read/write 独立 DSL，也不承载字段状态、校验元数据或 Codec 的生命周期设计。

具体端口名称和端口数量由物料注册的 Manifest 决定；统一 Binding 语义属于 Protocol，不允许各物料自行把 bindings 重新定义为初始化值或网络事件。

17 · SLOTS

Slots：容器组合与 children 简写

已收敛
一个规范的 Slots 模型
{
  "material": "bottom-sheet-editor",
  "slots": {
    "trigger": [{ "material": "insured-summary" }],
    "content": [
      {
        "$use": "insured-fields",
        "with": {
          "insured": { "source": "data", "scope": "insured", "path": "" }
        }
      }
    ]
  }
}

所有 Slot 在 Canonical 都使用数组；children 可作为 slots.default 的 Authoring 简写。Manifest 声明哪些 Slot 合法、各自允许一个或多个 ViewNode，以及 Material 对这些 Slot 的具体交互含义。

Slot 是视图节点组合位置，不能与普通 Props JSON 混淆，也不是一个“把组件插入任意 DOM 节点”的操作指令。

18 · TYPED TEMPLATES

Typed View Template Params：可直接落地的方案

已收敛
保留 Typed Data Params，但只复用已有 Data Schema 的类型。无需额外泛型系统、参数表达式语言或全局 Scope Registry。
最小 Typed Template Params
interface TemplateDataParam {
  schemaRef: string;   // 相对于 data.schema 根的 JSON Schema Pointer
}
interface ViewTemplate {
  params?: Record<string, TemplateDataParam>;
  node: ViewNode;
}
interface TemplateUse {
  $use: string;
  with?: Record<string, DataReference>;
}
模板定义只注解类型，不复制业务 Schema
{
  "viewTemplates": {
    "insured-fields": {
      "params": {
        "insured": { "schemaRef": "#/$defs/Insured" }
      },
      "node": {
        "material": "text-input",
        "bindings": {
          "value": { "source": "data", "scope": "insured", "path": "/name" }
        }
      }
    }
  }
}
调用方局部别名 item ≠ 模板参数 insured
{
  "scope": {
    "from": { "source": "data", "path": "/insureds" },
    "as": "item",
    "mode": "each"
  },
  "node": {
    "$use": "insured-fields",
    "with": {
      "insured": { "source": "data", "scope": "item", "path": "" }
    }
  }
}

参数只承担将一个可定位的数据位置引入模板词法环境的职责。L2 检查必需参数、引用可见性、Data Schema 来源、字段路径与 Material Port 类型。相同 $defs 定义引用优先视为兼容；复杂组合 Schema 若不能静态证明兼容，应明确诊断，而不是伪造保证。

定稿边界
V1 Template Params 只支持 Typed Data Reference。普通 title、theme、variant 等配置值尽量通过 Material Props 或复合物料解决；不加入模板泛型、动态模板选择和隐式捕获调用方 Scope。
19 · MATERIAL CONTRACT

Material Manifest：协议机制与物料限制分层

已收敛
外部注册契约 · 不内嵌到 FormDefinition
interface MaterialManifest {
  id: string;
  version: string;
  propsSchema?: JsonSchema;
  bindings?: Record<string, BindingPortContract>;
  slots?: Record<string, SlotContract>;
  events?: Record<string, EventContract>;
}
限制归属示例谁负责
L1 Protocolbindings 必须是端口到 Data Reference；ScopeNode 合法位置所有物料统一遵守
Material Manifesttext-input 的 placeholder、value 类型、confirm 事件；Modal 的 trigger/content Slot物料注册时声明
Form Definition18–65 周岁、证件必填、被保人最多 5 个Data Schema / Constraint

视觉/输入限制不等于业务数据校验。例如 maxLength 是 TextInput 的输入体验；真正的“姓名不能超过 20 字符”仍必须由 Data Schema 或 Constraint 保证。

Web 与 Flutter 可以实现不同交互形态，但同一物料契约下的 Binding Port、Event Payload、Slot 和 Props 语义必须兼容。Form Definition 需要通过可确定的版本解析规则绑定 Material Manifest；不能依赖不受控的“latest”。

20 · INTERACTION

Interaction：只保留数据命令和宿主事件

已收敛
受限 Event → Intent
type InteractionIntent =
  | { type: 'form.command'; command: Command }
  | { type: 'host.emit'; event: string; payload?: ValueSpec };
按钮语义事件与宿主能力连接
{
  "material": "button",
  "props": { "label": "提交" },
  "on": {
    "activate": {
      "type": "host.emit",
      "event": "insurance.submitRequested"
    }
  }
}

普通输入更新首先通过 Binding Port，不应同时要求 on.change → form.command 再写一次。Material 的打开、关闭、滑动、焦点、动画等属于其内部行为。

历史方案 · 不采用view.present → mode: modal / drawer

增加 View Controller、实例管理和 Presentation 契约，与容器物料职责重叠。

最终方案 · 采用modal / drawer / bottom-sheet Material

容器物料通过 Slots 组合已有 View Template，自行管理局部交互。

21 · HOST

Host Integration：明确三条路径

已收敛
场景Definition 表达外部负责
外部 Constraintkind: external + dependsOn + requiredForSubmit注册校验器、请求、上报状态与当前结果
用户触发外部业务on → host.emit根据事件契约执行业务流程
自定义物料服务Material Binding/Props 和外部注入服务契约远端选项、文件上传等私有物料服务

Host 异步响应后如果需要改变表单数据，应该调用 Runtime 的受控 Command API；Definition 不需要表达异步 Promise 链、请求重试或服务编排。授权与最终数据安全仍由 Host/服务端负责，不能因为表单本身有前端校验就直接信任提交结果。

22 · LIFECYCLE

初始化、更新、重初始化与提交

已收敛
操作语义约束
Initialize创建当前 Form 实例基线；Host 数据优先，缺失位置按规则补默认值
Update向当前 Working Data 提交受控数据修改；不是重新初始化
Reinitialize用新的外部初始数据建立新的当前基线；不假扮逐字段用户编辑
Reset回到当前初始化基线，不是必然回到第一次加载的旧基线
Submit / Readiness内外约束以及输出完整性符合要求后，由 Host 执行真实提交

Definition 不增加 onInit、onReset、beforeSubmit 等通用生命周期脚本。宿主 API 的具体返回值或事务流程属于 L3/Host 实现，但上述生命周期的语义差异必须保持。

23 · DELIVERY

多 Profile 与按需交付

已收敛

View Profile 表达同一业务数据在不同终端或场景下采用不同的物料树。服务端或 L2 可以按请求只准备当前 Profile 的入口与其静态引用依赖，但共享 Data Schema、Constraint、Reaction 不能仅因为某字段不可见就被裁剪掉。

Profile 是选择入口，不是复制 Form Definition

      "entry": { "$use": "expanded-form" }

30 · TYPES APPENDIX

附录：完整的核心类型关系（概念稿）

待固化
架构核心类型汇编（用于后续正式 TypeScript 固化）
type JsonPrimitive = string | number | boolean | null;
type JsonValue = JsonPrimitive | JsonValue[] | { [key: string]: JsonValue };
type JsonSchema = Record<string, unknown>; // 采用正式 JSON Schema 类型

type DataReference = { source: 'data'; path: string; scope?: string };
type ContextReference = { source: 'context'; path: string };
type EventReference = { source: 'event'; path: string };
type Reference = DataReference | ContextReference | EventReference;

type ScopeBinder = {
  from: DataReference;
  as: string;
  mode?: 'one' | 'each';
};
type ScopeDeclaration = ScopeBinder | ScopeBinder[];
type ScopeHandleReference = { $scope: string };

type Expression =
  | JsonPrimitive
  | { ref: Reference }
  | { use: string }
  | { op: string; args: Expression[] }
  | { literal: JsonValue };

type ValueSpec =
  | JsonPrimitive
  | { $expr: Expression }
  | { $literal: JsonValue }
  | ValueSpec[]
  | { [key: string]: ValueSpec };

type IssueDefinition = { target: DataReference; code: string };

type InternalConstraint = {
  id: string; kind: 'internal';
  scope?: ScopeDeclaration;
  when?: Expression;
  assert: Expression;
  issue: IssueDefinition;
};
type ExternalConstraint = {
  id: string; kind: 'external';
  scope?: ScopeDeclaration;
  when?: Expression;
  dependsOn: DataReference[];
  target: DataReference;
  requiredForSubmit?: boolean;
};
type Constraint = InternalConstraint | ExternalConstraint;

// Command 具体每种操作的字段请以正式 JSON Schema 为准
// 下方展示稳定的分发类别，非已完整定义的公开类型。
type Command =
  | { op: 'set'; target: DataReference; value: ValueSpec }
  | { op: 'patch'; target: DataReference; value: Record<string, ValueSpec> }
  | { op: 'remove'; target: DataReference }
  | { op: 'array.insert'; target: DataReference; value: ValueSpec; [k: string]: unknown }
  | { op: 'array.remove'; target: DataReference; item: ScopeHandleReference }
  | { op: 'array.move'; target: DataReference; item: ScopeHandleReference; [k: string]: unknown }
  | { op: 'batch'; commands: Command[] };

type Reaction = {
  id: string;
  scope?: ScopeDeclaration;
  watch: DataReference[];
  when?: Expression;
  then: Command[];
};

type InteractionIntent =
  | { type: 'form.command'; command: Command }
  | { type: 'host.emit'; event: string; payload?: ValueSpec };

type MaterialNode = {
  material: string;
  props?: Record<string, ValueSpec>;
  bindings?: Record<string, DataReference>;
  slots?: Record<string, ViewNode[]>;
  on?: Record<string, InteractionIntent>;
};
type ScopeNode = { scope: ScopeBinder; node: ViewNode };
type TemplateUse = { $use: string; with?: Record<string, DataReference> };
type ViewNode = MaterialNode | ScopeNode | TemplateUse;
type ViewProfile = { entry: ViewNode };
type ViewTemplate = {
  params?: Record<string, { schemaRef: string }>;
  node: ViewNode;
};

type FormDefinition = {
  protocolVersion: string;
  id: string;
  version: string;
  data: { schema: JsonSchema };
  expressions?: Record<string, Expression>;
  constraints?: Constraint[];
  reactions?: Reaction[];
  views: Record<string, ViewProfile>;
  viewTemplates?: Record<string, ViewTemplate>;
  metadata?: Record<string, JsonValue>;
};
不要误当成可直接发布的 npm 类型
本附录刻意把 array.insert / array.move 的具体位置描述留作固化项，且 JsonSchema 使用抽象占位。它是已收敛语义的汇编，不是已经编译与验证的完整类型包。
