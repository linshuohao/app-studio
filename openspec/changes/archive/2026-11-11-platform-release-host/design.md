# 发布与在线装载实施设计

以 [发布与 Host 契约](../../../../docs/design/platform-studio.md#authoring-publish) 和本提案为准。消费首存的稳定用户、权限检查、SQLite 写事务与精确版本读取。依赖历史预览切片的解析、Web 能力装配和归档写入接缝。

## 发布边界

Studio 冻结所选 `versionId` 与目标。保存并发布分两次授权和幂等操作，保存结果未知时重试原保存。后续编辑仍留在缓冲区。发布服务受理时持久化请求身份、输入指纹、精确版本关联和固定构建输入，编译在写事务外执行。固定输入包括实际能力目录、Schema 资源表、目标和 Compiler 构建身份。本地 Web 切片使用空的外部 Schema 资源表，配置中的本地引用继续由 Compiler 处理。

同键异参冲突，成功回执长期保留。相同用户持当前查看权限可重放已完成结果；发起或继续未完成的发布需要当前发布权限。未成功提交时重试读取原固定输入；固定 Compiler 构建不再可用时明确返回不可用。发布记录的唯一请求关联同时承担成功回执。

提交通过同一 SQLite 写事务复核账号、成员、发布权限及归档状态，一并写入 Prepared 原文、摘要、发布事实及审计。已受理请求主动退出后按当前账号及成员资格裁决。失败不产生可读取交付。审查用实际 SQLite 写连接和编译完成屏障验证提交顺序。

## 交付与 Host

根据本会话实施期间的用户确认，在线读取无需凭证。公开接口按指定 releaseId 交付已提交的响应格式、目标、Prepared 原文和 SHA-256 摘要。Studio 的发布记录和请求回执沿用工作台访问控制。首期示例返回 `no-store`，每次新装载重新取制品；现有实例仍固定其发布与装配。配置作者须了解 Prepared 内容会随发布公开。

摘要覆盖已存 UTF-8 Prepared 原文。示例 Host 核对响应身份、摘要、结构、格式、目标、能力锁和必要 Host 回调。能力锁使用构建包中的 Manifest 和由实际已构建文件导出的实现身份。API 和示例 Host 构建分别计算同一能力包的身份。Compiler 身份覆盖解析和校验依赖，避免待完成请求借升级替换固定输入。

示例 Host 使用本地城市数据、实例内草稿和校验后的本地提交反馈。预览模拟器独立。新装载丢弃过期响应，已有实例继续使用原交付和状态。首期支持当前 Web 装配可消费的新旧发布。能力升级后若当前 Host 缺少匹配实现，明确拒绝装载；旧能力包的分发由后续能力交付设计承接。

## 验证入口

- `services/api/test/platform-release.e2e-spec.ts` 使用 Nest HTTP、真实 SQLite 和第二个数据库连接，覆盖版本归属、权限、并发重试、提交复核、审计写入失败、固定构建不可用和匿名交付。
- `apps/studio/tests/release-host.spec.ts` 使用生产构建后的 API、Studio、Chromium 和真实 Runtime / Renderer，覆盖保存与发布响应丢失、归档后恢复成功回执、两个 releaseId 的独立实例、实际填写及 Host 校验、迟到响应、摘要和能力锁。
- `python3 tools/engineering/workflow.py verify platform-release-host` 在同一范围指纹下重跑切片检查。运行证据见同目录的收据。
