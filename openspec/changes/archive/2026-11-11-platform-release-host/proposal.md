# 发布确定配置版本与示例 Host 在线装载

## Why

创作者需要把明确选定的配置版本交付给 Host。一次发布从受理到重试都使用相同的构建输入。Host 凭 `releaseId` 获取已提交的不可变制品，使较新的配置保存、能力升级和发布都可以与旧交付并存。

现行依据是 [Platform / Studio 创作 MVP](../../../../docs/design/platform-studio.md#platform-authoring-mvp)、[单团队 RBAC](../../../../docs/design/platform-studio.md#platform-rbac)和 [ADR-FE-029](../../../../docs/design/decisions/ADR-FE-029-platform-config-versions.md)。ADR-FE-029 已替代 ADR-FE-028。首期模型为表单直接组织不可变配置版本，每次新保存追加 `versionId`。本提案承接总协调会话授权的第三个交付切片，供范围与行为评审。

## What Changes

### 范围与行为

1. **选择发布输入。**发布者可以发布所属表单的任一已保存 `versionId`，包括非最近版本。服务端校验版本归属、资源范围和发布权限。拥有编辑及发布权限时可发起“保存并发布”。界面冻结点击时的文本，复用既有保存操作，确认保存的结果后仅以该 `versionId` 发起发布。若保存失败或结果未知，先解决该次保存。等待期间的新编辑继续留在编辑器。保存成功而发布失败时，保留已保存版本并反馈发布失败。
2. **受理与固定输入。**以不可变配置原文、实际能力目录快照（含 Manifest、实现身份及已有的 Host 静态契约）、Schema 资源快照、目标（含选定 Profile 及目标格式）和确定 Compiler 构建身份固定本次构建。保留配置显式声明的能力选择，沿用检查切片的解析、诊断与编译输入装配。检查和预览的结果可供反馈，发布仍以本次固定输入完成准入。任一 Error 都不生成可读发布。
3. **幂等恢复。**同一发布操作重试复用已固定的输入。成功提交后即使响应丢失，也从原操作结果取得同一 `releaseId`，成功回执重放要求当前查看权限。发布操作标识绑定发起人、空间及请求指纹，在首次受理时登记固定输入。相同标识的并发请求收敛到同一操作，变更版本或目标后复用标识应报冲突。“保存并发布”的保存标识与发布标识分别复用，前者先确定唯一版本。
4. **复核与原子可见。**构建完成后，在与资格变更可确定先后顺序的提交边界，复核发起人账号、成员、当前发布权限、资源归属及表单状态。主动退出结束会话，已受理操作继续按发起人当前资格裁决。停用、撤权或归档先完成时拒绝提交，发布先完成时保留结果。制品、发布事实、成功审计与幂等成功结果一致提交后才对读取可见。若制品先写入独立存储，暂存对象在提交前保持不可读，提交失败后也不能通过读取接口或对象地址取得。
5. **示例 Web Host。**输入明确的 `releaseId` 在线取得已提交交付，校验响应身份、Prepared 字节摘要、结构、格式、目标与能力兼容性，装配所需物料、函数和示例 Host 适配后创建实例。Host 持有填写数据和业务回调。创建新实例时使用新选定的 releaseId，已有实例固定原交付和装配。获取或装载失败时显式反馈，避免把失败实例呈现为可正常填写。采用包含布局、条件、校验和 Host 请求或事件的可控示例完成闭环。

### 依赖与排除

| 前置切片                   | 消费边界                                                                                                                                                                                                |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `platform-first-save`      | 消费内置访问、稳定用户与成员身份、RBAC / 资源状态、不可变原文及保存幂等。实施设计需共同确定资格变更与发布提交的并发边界，覆盖停用、撤权及归档。                                                         |
| `platform-history-preview` | 复用解析与诊断映射、目标选择和 Compiler 输入装配，与本切片的归档 / 恢复操作共用表单状态提交边界。历史选择只传确定 `versionId`。发布模块负责固定并留存输入，预览的试填状态和模拟回调属于其自身生命周期。 |

本轮排除分支、覆盖确认、发布审批、灰度、可变渠道指针、专门的回滚操作、离线下载包、全量能力注册与分发后台、跨 Prepared 格式迁移及生产业务提交。GitHub 登录由独立切片交付。示例 Host 验收只覆盖明确支持的 Web 构建与能力集合。

## Impact

### 现有源码与实现影响

- **平台 API 与 Studio。**[Nest API](../../../../services/api/src/app.module.ts)当前仅有根模块脚手架。后续在同一模块化单体中接入发布用例，复用访问与创作模块的身份、版本读取和事务边界。Studio 在工作台串联保存与发布，在发布详情展示制品对应的配置版本、诊断和 releaseId。发布模块拥有构建输入快照、发布记录及在线交付。
- **Compiler。**[`CompileInput`](../../../../packages/compiler/src/types.ts) 接收 Definition、确定 Catalog、目标和 Schema 资源。[`compile`](../../../../packages/compiler/src/pipeline/compile.ts) 的失败分支交付诊断，成功分支交付 Prepared。[`assemblePrepared`](../../../../packages/compiler/src/output/assemble.ts) 写入包版本、Catalog ID、所选视图及可选平台，并闭合资源、能力锁和 Host Requirements。包版本和 Catalog ID 是追踪字段，发布侧仍须能定位不可变的 Compiler 构建及快照内容，以便重试和追溯。
- **Prepared 编码与摘要。**[`PreparedForm`](../../../../packages/protocol/src/prepared/form.ts) 是 JSON 形状，当前 Compiler / Runtime 格式为 `form-engine.prepared/2`。[`capturePreparedForm`](../../../../packages/protocol/src/internal/prepared.ts) 复制、校验并冻结已解析对象，其弱身份只在进程内有效。现有入口没有发布响应编码或整份 Prepared 摘要校验。候选做法是持久化编码一次的 UTF-8 JSON 字节与 SHA-256，Host 在可信响应中取摘要，校验解压后的原始 Prepared 字节再解析和做结构检查。避免对经过解析、重排字段或再次序列化的 JSON 校验字节摘要。
- **双摘要能力锁。**[L2 双摘要契约](../../../../docs/design/l2-preparation.md#capability-digest-contract)分别定义 Manifest 内容摘要与实际实现制品摘要。[`createCapabilityCatalog`](../../../../packages/compiler/src/capability/catalog.ts) 计算 Manifest 摘要并记录 Catalog 提供的实现身份。[`loadCompiledForm`](../../../../packages/runtime/src/lifecycle/load.ts) 检查结构、格式及函数锁。[`validateRenderInput` 与 `createRenderEnvironment`](../../../../packages/renderer-react/src/renderer/create-render-environment.ts) 检查视图兼容与物料锁，物料或请求缺失可表现为局部诊断。示例 Host 的装载门禁要覆盖必要依赖，并保留核心 Renderer 的既有局部降级语义。实现制品的身份来自可信构建清单或经验证的实际制品，当前 Demo 的[夹具摘要](../../../../apps/playground/src/demos/catalog.tsx)只供本地验证。
- **示例 Host。**[差旅 Demo](../../../../apps/playground/src/demos/travel/session.ts) 已演示函数、请求、校验和事件装配，当前在 Host 本地编译配置。新增在线消费路径复用装配与实例管理方式，直接消费下载的 Prepared。旧发布可用性依赖旧制品与匹配装配的留存。能力缺失、摘要不符或格式不兼容时显式失败。首期旧版本验收以支持范围内的两次发布为基线，并测试能力身份变化后的精确匹配。

### 可测验收

| 验证入口              | 正例和反例                                                                                                                                                                                                                                                                                    |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 发布 API 与持久化集成 | 从同一表单保存 V1、V2，选择 V1 发布并验证 release 关联、制品内容、目标和审计均对应 V1。仅编辑者、跨表单或越权版本请求被拒绝。归档后的表单拒绝新发布，已提交发布仍可按 releaseId 公开取得。                                                                                                    |
| Studio 与保存 API     | “保存并发布”点击后继续编辑，返回的版本和发布均对应点击时文本，后续编辑仍未保存。模拟保存响应丢失，结果未知期间无发布请求，重试恢复同一版本后再发布。保存失败无发布，发布失败仍能重开该已保存版本。仅有发布角色的成员可以发布旧版本，直接调用保存仍被拒绝。                                    |
| 固定输入与幂等        | 在受理后替换当前 Catalog、Schema 或 Compiler，并追加 V2。并发或进程重启后重试原操作时，断言仍使用已固定输入，或在该确定输入不可取得时明确失败。模拟提交后响应丢失，授权重试取回原 releaseId，仅有一个可读发布和一个成功审计。同键改版本或目标时返回冲突。                                     |
| 提交竞态与故障注入    | 用屏障停在构建完成与提交之间，分别让停用账号、停用成员、撤销发布权限、归档先提交，断言无新可读制品、发布或成功审计。倒转顺序，断言发布保留。主动退出后，仍具资格的已受理操作可提交，新请求按会话鉴权。注入编译 Error、制品写入失败及事务中途失败，验证读取与成功结果无半提交状态。            |
| Host 在线端到端       | 分别加载已发布的 R1、R2，使用各自的布局、条件、校验与受控 Host 交互。切换选择后新实例使用 R2，R1 的存量实例保留版本及填写状态。模拟慢 R1 响应晚于 R2，过期响应不覆盖当前选择。                                                                                                                |
| Host 准入与访问反例   | 匿名读取已提交的发布，未知 releaseId 返回未找到。Studio 发布记录与成功回执使用当前查看权限。失败不启动新实例。另测身份错配、篡改 Prepared 字节、结构错误、不支持的格式 / 目标、必要能力缺失、同版本异 Manifest 或实现摘要，以及必要 Host 适配缺失。确认兼容旧装配可用，新装配不能冒充旧实现。 |

验收为待实施场景。源代码核对与 OpenSpec 提案状态仅提供本轮评审证据。

### 风险与待评审决定

1. **在线读取与回执。**实施期间用户确认 Host 按 releaseId 公开读取。Studio 同键异参冲突，成功回执长期保留并按当前查看资格重放，未完成操作使用当前发布资格。示例 Host 本轮每次新装载在线读取，响应使用 `no-store`。
2. **旧能力制品。**本轮验收两个可并存的 Web 发布及其确定构建身份。若当前 Host 装配与旧能力锁不匹配，明确拒绝装载。后续多版本能力分发与跨 Prepared 格式迁移仍待设计。

事务或暂存布局、摘要实现复用位置、内部模块与存储命名属于实施设计。实施前须证明资格复核与发布提交共享有效的一致性边界，单独在事务外再读一次权限无法解决提交竞态。

## 协调评审 · 2026-11-11

范围及验收通过评审，等待首存契约与检查装配。业务身份统一为 versionId 和 releaseId。实施期间用户进一步确认 Host 公开读取，替代早期的 Host 凭证建议。响应携带确定的 Prepared 字节或等价原文编码及摘要，Host 在解析前校验。验收使用明确留存的兼容 Web 制品。缓存及恢复行为见本切片实施设计。发布可见性和资格变更必须有可验证的提交顺序。
