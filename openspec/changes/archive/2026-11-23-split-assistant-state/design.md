# 实施与证据

现行契约见 docs/design/platform-studio.md#agent-conversation-draft-ownership。迁移期间锁定源表，分页导出到 Agent 所有者的离线导入器，逐行读回校验。API 迁移在同一事务内校验源行及交付凭据、提取业务草稿并移除旧表。运行服务各自只使用本服务的数据源。重复运行应可安全收敛；发生差异时保留原表供核对。

## 本次切换与验收

本机源库共有 3 个会话、4 个轮次，平台保留 1 份独立草稿。迁移后逐会话比对，并使用实际服务账号核验新表权限；候选、工作稿、预览身份及正式表单与版本数量均已对平。一次性导入器只在离线维护时读取旧结构。

隔离双库演练另覆盖 4 个会话、5 个轮次，含零轮次的长首条输入、已保存版本，以及候选与手工工作稿内容不同的草稿。演练核验未对账时拒绝删除旧表、重复执行幂等，以及删会话后工作稿完整。浏览器用可重复模型、真实 Graph、Compiler 和两套临时数据库验证手改、删除、重开、预览和保存；另一条用例验证正式保存后继续同一会话并刷新。入口为 `apps/studio/tests/run-agent-ownership.mjs` 及其 `--promotion` 模式。

独立审查发现并修复了迁移时首条消息截断、保存后的编辑资源与会话错配、异步离开编辑器及脏缓存覆盖工作稿的问题。Agent 的 PostgreSQL 测试验证会话写入排他、不同会话并行和切换锁；API 集成测试覆盖重复交付、版本冲突及草稿独立访问。
