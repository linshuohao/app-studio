# 首存切片实施设计

- `services/api` 内部按平台存储、成员访问、表单创作分工。平台数据库使用 Node 内置 SQLite、外键、带版本迁移和同步写事务。每个写事务覆盖资源条件及其业务记录和回执。初始化由独立 stdin CLI 执行，数据库路径由 `PLATFORM_DB_PATH` 配置。
- 成员访问拥有用户、成员角色、内置凭据和会话。密码由带随机盐的 scrypt 派生。Cookie 携带随机令牌，数据库只存摘要。会话保留来源，建议本地固定八小时有效期，未来访问切片可在共享契约中调整。Studio Origin 由服务端配置，写操作拒绝其他来源。HTTPS 配置启用 Secure。
- Studio 同源代理 `/api/platform/*` 到 Nest。应用接口为访问上下文、登录、退出、表单列表和创建、打开及保存。使用标准 HTTP 状态区分未登录、缺权、未找到和同键异参。客户端通过 `Idempotency-Key` 复用提交。同键按空间、用户和操作隔离，校验请求指纹及当前资格。写入和回执同事务完成。
- 配置文本初始值为 `{}\n`，首轮上限为 16 KiB UTF-8，允许无效 JSON。按数据库写入序列取最近版本，原文按 UTF-8 字节保存。版本精确读取留在表单创作模块，作为后续历史和发布的接口。归档后沿用同一写事务裁决。
- Studio 页面持有本地编辑和冻结的提交快照。结果未知时可以重放同一快照，期间输入保留。离开工作台时提示未保存输入。首次交付以实际 Chromium 和单实例持久目录为验收环境。

## 实现与独立复核

- 初始化、身份和权限见 `services/api/src/platform/bootstrap.ts`、`access.ts`。`issueSession(userId, source)` 写入带登录来源的会话，`contextForUser(userId)` 从当前资格导出访问上下文。调用方应先完成其自身身份认证，再签发会话。
- `PlatformForms.readVersion(spaceId, formId, versionId)` 在表单创作模块内复核空间、表单及版本归属。历史和发布调用方先检查各自的业务权限。写入在 `PlatformDatabase.write` 的同步事务内检查资格和状态，发布提交与归档可复用此边界。
- 独立审查在 `fd96b3c` 工作区基线上检查了初始实现并复核修复。Studio 在退出期间锁定输入，返回列表或重开时获取当前权限，待确认的请求在重试遇到权限拒绝时保留原键和输入。恢复权限时验证仍是同一用户。创建回执成功后，即使打开失败，已建表单仍可从列表打开。
- API 集成用临时 SQLite 与独立 Node 进程覆盖重启、写入回滚与重试。Studio Chromium 验证真实同源链路，使用浏览器网络拦截构造响应丢失、权限拒绝及打开失败。真实角色变更另由 API 集成测试覆盖。
