# GitHub 登录实施设计

[现行契约](../../../docs/design/platform-studio.md#platform-github-login)定义一对一身份、近期内置密码确认，以及本地解绑和上游撤销边界。沿用首存身份、SQLite、同源 Cookie 和当前 RBAC。

## API 与事务

访问模块管理绑定历史和独立递增的绑定身份。SQLite 部分唯一索引约束双向有效归属。绑定开始保存会话、用户和当前绑定历史序号，回调提交复核相同会话、短期证明与序号。GitHub 登录流程保存发起时的绑定序号上限，拒绝发起后新增的绑定。以绑定标识作为 GitHub 会话来源，写事务内复核绑定和资格再签发。解绑与该来源会话撤销同事务提交。

登录发起为匿名浏览器准备随机 HttpOnly 凭据，回调成功才将该凭据激活为共享平台会话。回调与解绑响应均不重写 Cookie，避免迟到响应覆盖退出或其他登录。解绑后的旧凭据由访问接口拒绝。内置登录与退出撤销请求携带的前台凭据及其在途 OAuth 流程。OAuth state 原子消费，GitHub 网络请求在事务外执行，最终事务再次校验流程。GitHub 密钥仅在 API，令牌只用于读取当次身份。

## Studio 与验证

登录页和列表消费 API 的启用及绑定状态。GitHub 回调经 Studio 专用路由转发，响应只允许固定本地目标，避免上游代理失败记录授权参数。Chromium 使用真实 Studio、API 和数据库以及测试专用 GitHub 替身。发布与匿名 Host 使用现有路径联验。真实 OAuth 依赖部署侧提供现成 OAuth 应用、凭据和匹配的回调。
