# 首期 GitHub 登录

状态：2026-11-14 用户确认规则，按现行设计实施。原待评审记录见下文。

## Why

首期使用者通过受控初始化取得内置账号。此变更让该用户绑定 GitHub，之后可任选一种方式登录同一个平台用户，并继续使用同一个空间成员身份及现行权限。已确认的登录范围与验收依据见[首期 MVP](../../../docs/design/platform-studio.md#authoring-acceptance)、[现行 ADR-FE-029](../../../docs/design/decisions/ADR-FE-029-platform-config-versions.md)和[协调确认来源](../../../docs/design/source-map.md#src-platform-simplified)。

ADR-FE-029 已替代 ADR-FE-028。首期由表单直接组织配置版本，每次新的成功保存追加一个 `versionId`，分支与覆盖确认已移出首期。本切片沿用该边界，两种登录方式产生的操作都以同一平台用户归因。[创作模型](../../../docs/design/platform-studio.md#authoring-models) · [保存规则](../../../docs/design/platform-studio.md#authoring-save)

## What Changes

- **绑定**。在已登录的内置账号下发起 GitHub 授权，服务端核验回调及 GitHub 身份后，将其关联到当前平台用户。建议使用 GitHub 返回的稳定账号 ID 建立唯一绑定，避免改名破坏绑定、同邮箱误关联或同一 GitHub 身份跨用户复用。
- **登录**。完成 GitHub 授权后查找已有绑定，并经共享会话入口登录同一个平台用户。未绑定账号拒绝登录，引导先用内置账号登录并完成绑定。登录不创建平台用户、成员或角色。
- **解绑与会话**。增加解绑入口，保留内置凭据作为恢复路径。评审本地绑定失效、在途回调、存量会话及重新绑定之间的行为。账号、成员和角色撤权沿用服务端规则，前端状态不能提供旧权限。[RBAC 模型与执行](../../../docs/design/platform-studio.md#platform-rbac) · [授权时点](../../../docs/design/platform-studio.md#rbac-enforcement)
- **回调与反馈**。覆盖用户取消、状态不匹配、过期、重放、提供方故障、绑定冲突和配置缺失。候选流程按登录或绑定区分回调目的，绑定原发起浏览器及对应平台会话，使用短期、单次消费的状态并配合 PKCE。回调地址由服务端配置，客户端仅接收可恢复的失败信息。[GitHub OAuth Web 流程](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps)

**范围排除。** 自助注册、邮箱合并、GitHub 组织或仓库授权、成员与角色管理扩展、其他身份提供方、Host 身份、表单创作和发布行为均在本切片之外。外部 OAuth 应用的创建、配置与凭据发放由部署侧另行提供，本切片不创建外部应用。

## Impact

- **依赖及并行边界。** [platform-first-save](../platform-first-save/proposal.md) 负责初始化、稳定平台用户 ID、内置凭据、平台会话与鉴权入口。GitHub 切片复用同一会话签发和撤销机制，并依赖其有效账号与成员查询。接口需共同核对会话签发时的资格检查、按登录来源撤销会话的可行性，以及角色变更后的请求判定。首存提案建议同源 Cookie 和服务端持久会话，其部署与有效期仍待评审。本切片复用最终接缝。历史与发布切片可并行，继续使用平台用户和既有鉴权。已受理发布的提交资格复核由发布切片负责，主动退出的既有语义按现行设计执行。[发布提交边界](../../../docs/design/platform-studio.md#authoring-publish)
- **源码基线。** 核对 `fd96b3c` 及当前工作区，`services/api/src/app.module.ts` 未导入业务模块，`app.controller.ts` 仅暴露根路径示例，`main.ts` 负责启动，`services/api/.env.example` 只列出监听配置。现有 Next 应用是 Playground。平台访问模块与 Studio 登录入口待交付，路径及最终接口由首存切片对齐。[模块化单体](../../../docs/design/architecture.md#platform-modular-monolith)
- **预计落点。** 在 Platform API 访问模块内新增 GitHub 提供方适配、绑定持久化与约束、授权状态与回调处理，复用内置登录的会话签发和 RBAC。Platform Web / Studio 消费 GitHub 登录、绑定状态、解绑和失败反馈。部署侧需提供 OAuth Client ID、Client Secret 和可达的回调 URL，服务端保管 Secret。具体路由、字段、存储结构和测试命令留待评审后按项目流程细化。[OpenSpec 衔接](../../../docs/design/workflows.md#workflow-openspec)
- **主要风险。** 账号串绑、回调重放或开放重定向可能导致登录劫持。绑定唯一性与回调单次消费需覆盖并发，解绑或停用与回调并发时需验证最终会话资格。凭据、授权码、令牌及回调状态须避免进入浏览器持久存储和日志。建议令牌仅用于服务端读取必要身份，不为登录请求邮箱、组织或仓库额外权限。真实 GitHub 往返受部署配置限制，受控提供方可覆盖集成反例。

## 可测验收

| 场景                                                         | 可观察结果                                                                                                                                                                                                                          |
| ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 内置用户完成绑定，退出后分别用内置和 GitHub 登录             | 两次登录得到同一平台用户、同一空间成员及当前有效权限。受保护操作归因于同一用户。                                                                                                                                                    |
| 未绑定 GitHub 身份登录，包含与内置账户显示邮箱相同的情况     | 无新平台会话、用户、成员或授权。用户可回到内置登录。                                                                                                                                                                                |
| 回调缺失或伪造 state、已过期、已消费，或绑定期间换了平台账号 | 候选。拒绝完成回调，无新绑定或会话。并发重复回调至多有一次有效结果。                                                                                                                                                                |
| 用户取消授权、换码超时或 GitHub 身份读取失败                 | 候选。显示可重试结果，无部分绑定或新会话，已有内置会话可继续使用。                                                                                                                                                                  |
| 同一 GitHub 身份被另一个平台用户并发绑定                     | 候选。最多归属一个平台用户，冲突不覆盖已有绑定。                                                                                                                                                                                    |
| 本地解绑完成后再次 GitHub 登录，或完成解绑前已发起的登录回调 | 候选。失效绑定不再签发会话，既有 GitHub 来源会话按评审确定的规则失效，内置方式仍可登录。用受控时序验证解绑与登录或重新绑定回调交错，旧回调不得恢复已删除的绑定。                                                                    |
| 修改角色、停用成员或停用账号后，使用 GitHub 建立的会话访问   | 新受保护请求按当前资格判定。角色回收后拒绝相应操作，停用账号或成员后拒绝受保护资源。以真实服务端响应验证。                                                                                                                          |
| GitHub 侧撤销授权后，回调换码或身份读取被拒绝                | 候选。回调失败时无新平台会话。先前签发的平台会话是否联动失效见待决项。                                                                                                                                                              |
| 部署未提供配置、配置不完整或回调 URL 与 GitHub 注册不符      | 候选。配置缺失或本地校验失败时 GitHub 入口不可用。GitHub 在上游拒绝回调 URL 时，可能停在 GitHub 错误页，需核对部署配置。两种情况下内置登录仍可用，应用可见的错误与日志均不含密钥。真实往返需由部署侧提供现成 OAuth 应用及匹配回调。 |

## 待评审决定

1. **绑定和解绑的身份确认。** 建议要求近期验证内置凭据，成功前复核发起会话和用户仍有效。需确定是否接受近期 GitHub 登录证明，以及首期是否限制每个平台用户仅绑定一个 GitHub 身份。这些选择决定绑定入口、冲突处理及替换流程。
2. **本地解绑的会话范围。** 建议失效该绑定签发的既有会话及依赖旧绑定的在途登录，保留内置方式建立的会话。若共享会话层仅支持用户级撤销，需与首存切片明确来源记录或评审全用户退出的行为。另需明确主动退出仍按共享会话规则处理。
3. **GitHub 侧撤销的联动。** 本地解绑、平台撤权和 GitHub 上游授权撤销各有独立生效点。建议首期在每次 OAuth 往返验证身份，存量平台会话按本地规则失效。若要求 GitHub 侧撤销立即终止平台会话，需确定可用信号、可靠性和失败时语义。另需决定本地解绑是否同步撤销 GitHub 侧应用授权，及提供方失败时本地解绑是否仍完成。[GitHub 授权撤销接口](https://docs.github.com/en/rest/apps/oauth-applications)
4. **部署与真实验收依赖。** 确认用于验收的 Platform Web / API 公开入口、回调 URL、现成 OAuth 应用与凭据提供方。候选缺省行为是 GitHub 功能未配置时禁用该入口并保留内置登录。配置未到位时可验证受控 OAuth 集成，真实 GitHub 往返待补证。

## 协调评审 · 2026-11-11

范围与验收通过评审，等待首存用户及会话接缝。登录来源须能追溯到具体绑定，便于在实施设计里确定解绑的会话撤销范围。绑定、解绑以及上游撤销的外部行为仍按待决项收敛。受控 OAuth 回归可独立验收，真实 GitHub 往返依赖部署配置。

## 确认与实施 · 2026-11-14

用户在总协调会话确认完整方案，行为归入 [GitHub 登录与会话](../../../docs/design/platform-studio.md#platform-github-login)。首存接缝已实现，旧源码基线是提案历史。真实 OAuth 配置仍为外部验收前置。
