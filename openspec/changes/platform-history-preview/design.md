# 配置历史与预览实施设计

依据 [MVP](../../../docs/design/platform-studio.md#platform-authoring-mvp) 和本变更提案。首存实现已提供 `PlatformForms.readVersion(spaceId, formId, versionId)`、`PlatformDatabase.write`、同源 Studio 代理和独立的编辑缓冲。共享类型与路由以实施前源码为准。

## 历史与管理

列表、详情和精确原文查询从创作模块读取，先验证当前查看权限和表单归属。列表按现有写入序列排序。详情只读，继续编辑只切换本地起点，未保存缓冲由工作台统一处理。沿用原文大小上限、保存回执和幂等格式。

复制在同一写事务内验证来源与目标权限、创建表单及初始版本，并写入幂等回执。跨表单来源只允许由复制用例建立。重命名及说明编辑沿用编辑权限和基本条件更新。归档、恢复按表单管理权限更新状态并记录审计，保存与归档在同一写事务边界判定先后。

## 检查与预览

服务端接收冻结原文或确定版本之一，检查资格后解析并装配 Compiler。诊断保留严重程度与 Pointer，文本位置由同一冻结输入映射。使用已验收的 Web 差旅能力作为首个联验夹具。实际目录来源和支持目标需与发布切片共同落实。

浏览器为检查请求关联输入与操作序号。预览使用独立 Runtime、Renderer 和明确配置的模拟 Host。关闭、替换及离开时撤销结果资格，卸载并释放旧实例。测试以可控回调覆盖迟到结果。未配置模拟交互时的产品反馈沿用提案待决项。显式检查放在编辑工作台，历史只读页面的独立重新检查入口不属于已确认范围。

## 向发布交接

共享解析、诊断与 Web 能力装配，发布以自身固定的输入构建。提交检查与归档走同一事务边界。验收证据按 API 集成、浏览器工作台和真实引擎预览分别记录。

## 实施记录与发布依赖

- 实施起点为 `fd96b3c14f0ec668d5174762ff84c55255a8fc6c` 加已验收、尚未提交的首存工作区。开始前快照保留了暂存、未暂存及相关未跟踪文件。本切片与首存共享 API、Studio 源码及锁文件，保留工作区改动。
- SQLite v2 追加复制来源外键，保留普通保存原有的同表单外键。归档状态与审计同事务提交。元数据使用整数修订条件更新，Studio 仅将回执应用到发起操作的打开实例。
- API 以现有公开 Compiler 和静态 Manifest 构建 Web 夹具目录。Studio 单独注入匹配的物料、函数和模拟 Host。当前差旅夹具缺少必需模拟能力时显示不可用，跨目标和通用缺失能力策略仍在原提案评审范围。联验使用差旅桌面视图，沿用首存 16 KiB 原文上限。
- 发布切片可复用确定版本读取、原文定位和 Compiler 输入装配。发布需要自己的真实能力制品与资源锁定、幂等构建和提交资格复核。Web 预览夹具的制品身份与模拟 Host 仅用于试填。
- API 集成覆盖 v1 升级、精确历史、复制回执故障回滚、并发提交与 RBAC。Chromium 使用实际 Nest / SQLite 与 Runtime / Renderer，覆盖迟到检查、预览关闭时的 Host 取消、元数据串写反例、冻结复制重放以及生产网络零调用。独立审查复核后无未关闭 P0/P1。
