# 配置历史与受控预览

状态：提案，待总协调会话评审。

## Why

首次保存建立可恢复的原文记录。第二个交付切片让创作者找回准确的历史版本，基于它继续编辑或复制成独立表单，并在发布之前检查与试填指定输入。语法错误也应能留档，迟到的检查结果不能改变当前编辑内容的检查状态。

本提案依据 [ADR-FE-029](../../../docs/design/decisions/ADR-FE-029-platform-config-versions.md)、[创作 MVP](../../../docs/design/platform-studio.md#platform-authoring-mvp)及其[确认来源](../../../docs/design/source-map.md#src-platform-simplified)，采用 [form-change 工作流](../../../docs/design/workflows.md#workflow-openspec)。ADR-FE-029 已替代 ADR-FE-028。表单直接组织不可变的配置版本，每次新的成功保存追加 `versionId`，来源只用于追溯。分支、分支指针与覆盖确认均在首期范围之外。

## What Changes

### 版本历史、复制与归档

- P2 工作台从确定版本加载，普通重开以最近保存为默认编辑起点。P3 提供当前表单的版本列表及只读详情，展示确定 `versionId` 对应的原文、来源、保存人、时间和备注。切换版本或离开前处理未保存内容。
- “继续编辑”将所选历史版本加载为工作台的本地编辑起点。后续保存沿用首次保存切片的追加、幂等及编辑状态契约，记录 `basedOnVersionId`。打开历史或进入编辑本身没有保存副作用。失败或失去编辑权时保留本地文本。[保存与历史](../../../docs/design/platform-studio.md#authoring-save)
- “复制为新表单”使用用户选定的确定版本或明确冻结的本地原文，允许从归档表单的确定版本复制。校验来源查看权与目标创建所需的编辑权。成功一次性产生独立 `formId` 及其初始 `versionId`，原样保留所选文本并记录可确定的来源；同一复制请求重试返回原结果。新表单有自己的权限与历史，旧发布、旧历史和原资源授权均不随复制带入。[创建与复制](../../../docs/design/platform-studio.md#authoring-fork)
- P1 提供归档与恢复，服务端检查表单管理权限并保留操作审计。归档暂停常规编辑并保留历史，确定版本仍可按查看权读取。恢复原表单身份和既有历史。并发保存与归档按提交顺序判定，归档先提交时保存应拒绝，保存先提交时已追加的版本保留。[保存与历史](../../../docs/design/platform-studio.md#authoring-save) · [权限及审计](../../../docs/design/platform-studio.md#rbac-enforcement)

### 检查与预览

- 检查和预览分别冻结用户触发时的本地原文或所选 `versionId`，结果绑定该输入、实际能力集合与目标。未保存修改的检查或预览需要编辑权，已有可用版本可按查看权受控预览；所有受保护操作沿用服务端权限及资源归属校验。两项操作都没有自动保存副作用。[检查与预览](../../../docs/design/platform-studio.md#authoring-publish) · [权限映射](../../../docs/design/platform-studio.md#rbac-form-actions)
- 解析失败在原文上报告诊断。解析成功后复用 Compiler 的结构及语义检查，将可定位的诊断映射回请求所用的原文，并保留诊断来源。存在 Error 时禁止生成可执行 Prepared 或启动该输入的预览。诊断和运行结果都只归属其输入，晚返回的成功或失败不能覆盖较新操作，也不能让后续文本显示为通过。
- 成功编译的输入用独立 Runtime 与 Renderer 受控试填。预览 Host 只接入经过明确配置的试填能力，生产业务提交、草稿写入与真实生产数据均在其能力边界之外。关闭、替换预览或离开工作台时撤销旧实例的交付资格并释放资源，包括渲染订阅、在途请求及校验。实例释放后的回调不能更新当前界面。

### 后续切片

发布入口、构建发布、`releaseId` 与 Host 在线装载仅由后续 `platform-release-host` 接入。GitHub 登录由 `platform-github-login` 接入。永久删除、可视化编辑、诊断分析图、实时协作、自动合并和物料管理后台均超出本提案范围。

## Impact

### 依赖与现有接入点

- **前置 [`platform-first-save`](../platform-first-save/proposal.md)**：复用内置访问、服务端授权、表单标识、保存事务与幂等、确定版本读取，以及保存回执与本地未保存状态的处理。前置提案的常规保存校验同表单来源，跨表单的来源追溯由复制操作在核验源表单和源版本后建立。评审时对齐最近保存的排序、原文往返、重试与冲突反馈，以及保存与归档的共同提交边界。
- **Platform / Studio**：表单领域负责按归属查询历史、原子复制、状态变更及保存写入边界。Studio 负责只读与编辑的转换、未保存提示、诊断定位及预览生命周期。现有应用源码中的 Playground 提供引擎接入参考，Platform API 与 Studio 页面是本切片的实施工作。
- **Compiler**：[`compile`](../../../packages/compiler/src/pipeline/compile.ts)接收已解析的 Definition、能力目录、目标与 Schema 资源。[`Diagnostic`](../../../packages/compiler/src/types.ts)提供 `sourcePointer` 等信息，原文解析和文本区间映射应在创作接入层实现。Compiler 失败结果不含 Prepared，本切片无需引入完整 AnalysisReport。
- **预览 Host**：现有 [Playground 差旅会话](../../../apps/playground/src/demos/travel/session.ts)展示编译、受控事件与请求、校验及释放的组合；它只作为源码参考。[`FormRenderer`](../../../packages/renderer-react/src/renderer/form-renderer.tsx)管理呈现接入，调用方持有 Runtime。使用 [Runtime 的 `dispose()`](../../../packages/runtime/src/runtime.ts)及 [Renderer 的请求取消能力](../../../packages/renderer-react/src/requests/bridge.ts)，Studio 同时撤销迟到的 Host 回调和创建结果的交付资格。

### 可测验收

| 场景                | 预期证据                                                                                                                                                                                                                        |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 保存无法解析的 JSON | 含明确换行和空白的原文保存成功并得到新 `versionId`，重开及历史详情逐字符相同。检查给出解析定位，预览不创建 Runtime。检查前后的版本数量相同。可解析但含 Compiler Error 的文本也不能创建 Runtime。                                |
| 基于历史继续编辑    | 保存 V1、V2 后打开 V1，只读详情精确显示 V1。继续编辑并保存得到 V3，来源为 V1，V1、V2 内容不变。加载历史前有未保存修改时，取消切换可保留修改。                                                                                   |
| 精确复制            | 归档含 V1、V2 的源表单后选 V1 复制，目标只有一条初始版本，内容和来源都对应 V1。相同请求重试返回相同目标。来源无查看权或目标无编辑权时拒绝，复制事务中途失败时也无残留目标表单或版本。复制冻结的本地文本时，点击后的编辑不混入。 |
| 归档与恢复          | 分别控制归档、保存两种提交顺序并核对版本数、状态、审计与错误反馈。归档后仍能读历史，恢复后沿用同一表单与历史并能再次保存。无表单管理权的请求不能改变状态。                                                                      |
| 迟到诊断            | A 发起后修改为 B，先返回 B，再分别令 A 返回成功或错误，当前状态始终对应 B。仅修改为 B 而不再请求时，A 成功也不能使 B 显示通过。切换版本、能力集合或目标后重复验证。                                                             |
| 预览运行和释放      | 用含布局、条件、校验及 Host 交互的配置试填；通过可控 Promise 验证关闭、替换及离开后旧校验与物料请求失去交付资格，旧编译迟到时也不能创建新实例。观察 Runtime 释放和旧 Renderer 卸载，再开预览使用独立实例。                      |
| 生产副作用隔离      | 触发配置中的提交事件、草稿事件、远程选择与异步校验，记录网络和 Host 调用。允许的模拟回调返回受控结果，生产提交、写入与真实查询调用计数均为零。版本详情和预览还应覆盖跨归属或撤权后的访问拒绝。                                  |

实施阶段以存储和 API 集成验证权限、事务及重试，以可控异步测试验证迟到结果与释放，再用浏览器验证工作台的完整操作。上述场景是拟执行的验收。

### 风险与待评审决定

- **能力与目标来源**：待评审的是首期支持哪些目标，以及由哪个受控目录提供 Compiler、Schema 资源、Runtime 和 Renderer 所需的匹配能力。建议优先复用项目已验收的差旅能力及对应模拟适配。需确认缺失模拟能力时对创作者的行为：阻止该输入启动预览，或允许试填且在触发缺失交互时明确报不可用。两种方案均须隔离生产调用。
- **检查权限缺口**：已有可用版本的预览按查看权执行，修改文本的检查和预览按编辑权执行。若只读历史页要提供独立的“重新检查”入口，需评审该操作的权限及其与预览内部编译的关系。建议首期将显式检查入口放在编辑工作台，只读历史页提供已确认的受控预览。
- **实现风险**：JSON 解析与 Pointer 映射若读取了当前编辑缓冲区，旧诊断可能落到错误位置；以冻结输入生成位置并在回填时校验归属。取消请求本身无法保证底层工作停止，Studio 的结果交付必须受当前操作和实例生命周期约束。归档与追加若分离状态检查和持久提交，可能产生归档后的新版本，需与前置切片共享写入边界。

评审通过后再编写验收增量、实施设计与任务。公共行为缺口由总协调会话确认。
