# 退回商品质检与库存分流

门店或仓库收到同一笔原交易的退货后，由质检员逐条登记实收数量和实物状态。本单输出库存分流决定，只涉及待处理记录，不直接发退款或更改原销售记录。一次批量最多 20 条原交易明细，至少一条，顺序可调整。

## 收件信息

仓库寄回需要物流单号。切换到门店柜台时清除旧物流单号，收件日期和全部明细保持。相同物流单号可能装有多个原交易，物流单号本身不作为去重键。

| 字段               | 交付键           | 必填         | 输入与存值                                    |
| ------------------ | ---------------- | ------------ | --------------------------------------------- |
| 原交易单号         | `originalOrder`  | 是           | 6–32 个字符。                                 |
| 质检员             | `inspector`      | 是           | 2–40 个字符。                                 |
| 受理来源           | `origin`         | 是           | 门店柜台（`shop`）、仓库寄回（`warehouse`）。 |
| 签收日期           | `receivedDate`   | 是           | 真实自然日，格式 YYYY-MM-DD。                 |
| 物流单号           | `parcelNo`       | 按规则或选填 | 5–40 个字符。                                 |
| 整单复核备注       | `inspectionNote` | 按规则或选填 | 0–200 个字符。                                |
| 已逐项核对退回实物 | `confirmed`      | 是           | 布尔值，初始未勾选。提交时必须勾选。          |

## 原交易明细

每行有稳定的 returnId，须填写原交易明细编号。空行在交付前必须补齐或删除。

| 字段           | 交付键               | 必填         | 输入与存值                                                                                  |
| -------------- | -------------------- | ------------ | ------------------------------------------------------------------------------------------- |
| 原交易明细编号 | `originalLine`       | 是           | 2–32 个字符。                                                                               |
| 实收退件数量   | `returns`            | 是           | 1–500 的整数。                                                                              |
| 质检结论       | `disposition`        | 是           | 可入库（`restock`）、送维修（`repair`）、隔离待处置（`discard`）。                          |
| 质检原因       | `reason`             | 是           | 未使用（`unused`）、包装受损（`packaging`）、商品故障（`defect`）、配件缺失（`mismatch`）。 |
| 质检记录编号   | `inspectionEvidence` | 按规则或选填 | 4–40 个字符。                                                                               |
| 维修点编号     | `repairHub`          | 按规则或选填 | 3–30 个字符。                                                                               |
| 隔离库位       | `isolationBin`       | 按规则或选填 | 3–30 个字符。                                                                               |
| 明细备注       | `lineNote`           | 按规则或选填 | 0–160 个字符。                                                                              |

## 结论与后续资料

可入库仅接受未使用或包装受损。送维修仅接受商品故障或配件缺失，并需要维修点编号和记有复核结论的质检记录编号。隔离待处置接受包装受损、商品故障和配件缺失，需要隔离库位和质检记录编号。

切换质检结论后重验原原因，若不兼容，保留原原因并在该行提醒修改。修改为隔离时清除旧维修点，修改为维修时清除旧隔离库位，两种结论间切换保留共同的质检记录编号。改为可入库后清除该行的维修点、隔离库位和质检记录编号。

## 订单核验与错误归属

同一交易明细被分多箱送回时，可否拆成不同质检结论分别入单，待售后确认。交易服务返回授权可退数量，以及此前已确认受理的数量。校验接收的原明细属于该交易且实收退件数量不大于剩余可退数。跨行重复在每条相关原明细出错，数量错误定位到具体行的实收数量，交易关闭或不存在定位在原单号。查不到或超时不允许继续交付，但保留本单。

## 快照、并发与交付

核验始终绑定当前原单号、各明细编号和数量。修改数量、增行、删行或换单应使旧核验结果失效。旧失败不得覆盖新单的结果。提交端用原单号和本次提交键防重复，写入前重新确认剩余可退数，避免另一张单刚占用余额。失败时保留工作值并指出受影响行。

交付包含收件方式及适用物流单号、原单号、收货日期、质检员、签收明细和当前适用资料。下游按结论分可入库、送维修和待隔离队列。

## 验收场景

1. 仓库寄回填写物流单后切到门店柜台，物流单号清除，原交易明细保持原样。
2. 选择送维修、原因为商品故障，补齐记录和维修点；改为隔离，维修点消失，质检记录仍在，隔离库位必填。
3. 原交易明细已卖 6 件、已受理 2 件，当前申请 4 件可通过，5 件错误定位在该行数量。
4. 请求 A 尚未返回便删掉一条、改了另一条数量，A 返回不得恢复删掉的明细，也不得放行新数量。
5. 初次核验通过后，另一张单占用一件额度，本次提交应指出剩余数量变化，不创建库存分流记录。
6. 断网时明确暂时无法核验，已有质检记录和关联资料保留；重试只按新快照执行。
