# 展会多会场议程与值岗确认

展会统筹将会场议程与排班同时交给场馆。表单面向已立项活动。场馆维护房间容量、可用房间和工作人员目录，随着活动日期变化可能需要重新核验。输出的是场馆确认请求，发布门票由独立业务系统处理。

## 活动和验票安排

一个项目占用一个场馆，可在场馆内排多个房间。活动连续 1–7 天，起止均现场当地自然日。容量上限适用于同一时刻实际在场的人数。

| 字段                       | 交付键           | 必填         | 输入与存值                               |
| -------------------------- | ---------------- | ------------ | ---------------------------------------- |
| 活动项目号                 | `eventCode`      | 是           | 5–28 个字符。                            |
| 会场编号                   | `venueCode`      | 是           | 3–24 个字符。                            |
| 现场统筹人                 | `organizer`      | 是           | 2–40 个字符。                            |
| 统筹邮箱                   | `organizerEmail` | 是           | 使用有效邮箱。                           |
| 活动开始日                 | `firstDay`       | 是           | 真实自然日，格式 YYYY-MM-DD。            |
| 活动结束日                 | `lastDay`        | 是           | 真实自然日，格式 YYYY-MM-DD。            |
| 场馆核定人数               | `capacity`       | 是           | 10–3000 的整数，单位为人。               |
| 现场验票方式               | `entryMode`      | 是           | 名单核验（`list`）、二维码核验（`qr`）。 |
| 名单核验台编号             | `checkinDesk`    | 按规则或选填 | 2–20 个字符。                            |
| 二维码批次号               | `qrBatch`        | 按规则或选填 | 4–32 个字符。                            |
| 确认与场馆和讲者核对后提交 | `approved`       | 是           | 布尔值，初始未勾选。提交时必须勾选。     |

## 会场议程

至少一场、最多 40 场。每行有稳定 sessionId。开始和结束采用分钟值，例如 9:30 为 570，24:00 为 1440。结束 1440 只表示当日结束；跨午夜议程需要分成两行。

| 字段                 | 交付键          | 必填         | 输入与存值                                                       |
| -------------------- | --------------- | ------------ | ---------------------------------------------------------------- |
| 议程标题             | `sessionTitle`  | 是           | 3–80 个字符。                                                    |
| 房间编号             | `roomCode`      | 是           | 2–20 个字符。                                                    |
| 议程日期             | `sessionDay`    | 是           | 真实自然日，格式 YYYY-MM-DD。                                    |
| 开始时刻             | `startMinute`   | 是           | 0–1439 的整数，单位为分钟（自当日零点起）。                      |
| 结束时刻             | `endMinute`     | 是           | 1–1440 的整数，单位为分钟（自当日零点起）。                      |
| 预计现场到场人数     | `seats`         | 是           | 1–3000 的整数，单位为人。                                        |
| 主讲人编号           | `speakerNo`     | 是           | 3–24 个字符。                                                    |
| 议程形式             | `kind`          | 是           | 演讲（`talk`）、工作坊（`workshop`）、带直播的议程（`stream`）。 |
| 工作坊分组与器材说明 | `materials`     | 按规则或选填 | 12–200 个字符。                                                  |
| 直播频道编号         | `streamChannel` | 按规则或选填 | 4–24 个字符。                                                    |

## 值岗安排

至少一条、最多 50 条。每行有 shiftId。排班必须覆盖活动的现场协调区间，场馆接收按日期及时段投影后的人员安排。

| 字段         | 交付键        | 必填         | 输入与存值                                                          |
| ------------ | ------------- | ------------ | ------------------------------------------------------------------- |
| 工作人员编号 | `staffNo`     | 是           | 3–24 个字符。                                                       |
| 岗位类型     | `team`        | 是           | 现场协调（`safety`）、签到接待（`reception`）、技术支持（`tech`）。 |
| 值岗日期     | `dutyDay`     | 是           | 真实自然日，格式 YYYY-MM-DD。                                       |
| 值岗开始时刻 | `startMinute` | 是           | 0–1439 的整数，单位为分钟。                                         |
| 值岗结束时刻 | `endMinute`   | 是           | 1–1440 的整数，单位为分钟。                                         |
| 交接备注     | `dutyNote`    | 按规则或选填 | 0–160 个字符。                                                      |

## 本地联动及错误归属

活动日期顺序错误归到结束日；只改活动日期时保留既有议程和岗位行，并重验落在日期范围外的行。议程形式为工作坊时器材说明必填；带直播的议程要求频道编号；两者切换时立即清除原形式独有资料，保留房间和对应人员。工作坊与直播可分别出现在不同的两行。

名单核验要求填写核验台编号，二维码核验要求填写批次号。切换后清除原方式字段，不清除会议议程。场馆核定人数由负责人确认填写，每场预计人数不得大于该值。场次的更小房间上限由目录另外核验。

## 场馆排程与讲者冲突

同一房间、同一天的两场议程可首尾相接，上一场 10:30 结束且下一场 10:30 开始视为无冲突。同一主讲人不得同一天在两场时间重叠的议程出现。比较使用半开区间 [开始, 结束)，相邻时刻不算交叉。跨日同房间同时间允许，每场房间和主讲人必须存在于项目目录。单场人数超过房间配置上限归到本场预计人数。

当多个房间并发使用，对结束与开始时刻相同的两场先去除结束场人次再加入开始场人数，逐时段比较容量。单场都合格，但同时段总人数超额时在活动核定人数项显示错误并标出冲突时段。修改一场人数后须重算它参与的所有时段。

## 场馆人员与值岗覆盖

工作人员编号按去首尾空白与英文字母大写后的值比较。同一天同一人不得有相交的值岗记录，即使两个岗位类型不一样。重复或时间冲突显示在两条值岗的开始时刻。议程开放的每一分钟均至少有一名现场协调人员在岗，可由交界相同的多段班次合并覆盖。技术支持和签到接待的班次不能替代这个岗位。存在断档时给当天最早受影响的议程标记提示。全单目录核验由 Host 完成。

## 回包、状态和交付

项目号、场馆号、活动日期、议程和班次均属于核验读集。只有返回适用于当前资料的结果才可辅助发布确认请求。长时间未返回时允许用户继续编辑，过期返回不能把任一现行错误覆盖或把本次判为通过。

接收端以活动项目号和提交键防重，提交前复核房间资源与人员是否仍可用。至少输出场所在日期、时段、预计人数、主讲人编号、场次形式及当前适用内容、排班岗位与人员编号。日期先后和同日明确的开始时刻决定下游展示排序。原表的行 ID 保留，输出排序不再重新分配。

## 验收场景

1. 5 月 1 日 09:00–10:30 与 10:30–11:00 同一个房间，容量符合时可通过。后一场改到 10:29 开始，两个场次的时间字段都显示冲突。
2. 两个房间同一时间分别以 180 人和 170 人开场，场馆限额为 300，两行各自未超房间容量但整段超限。把人数调整为 150 和 150 后通过。
3. 同一个讲者在两房间安排相同时间，即使人数合格也有冲突。改成下一天相同时间可通过。
4. 上午 09:00–12:00 有议程，协调值岗为 09:00–10:30 与 10:31–12:00，10:30 有一分钟无人，不能通过。把第二班提前一分钟并由另一名工作人员承担可覆盖。
5. 删除中间一条工作坊议程，后一条直播的频道编号和原行错误继续归于那一行。把直播改为演讲后只清除该行频道。
6. 核验发出后换场馆，旧房间可用结果作废。新场馆无法查到旧房间时提示房间项；先前班次仍保留可以调整。
7. 已审核的安排再次点击确认且提交键相同，场馆仅收到一份确认请求。写入前房间资源被另一个活动占用时报告场次错误。
