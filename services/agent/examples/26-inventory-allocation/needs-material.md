# 多站点库存调拨和额度确认

区域仓库用一张单把库存分配给多个收货点。每单固定一个发货仓、一辆车和一个发运自然日，发生分批发车时另开单。调拨只预约与创建出库任务，不记录运输签收或结算。录入者通常先把所有收货点建好，再分配库存，也可以先建空调拨行。

## 调拨单和运输约束

运输额度录入整数升。发货仓和发运日共同确定库存可用性，优先级只影响任务调度，不能突破库存和额度。优先配送要求理由，恢复常规后清掉理由。调拨任务号随工作草稿保留。

| 字段                 | 交付键           | 必填         | 输入与存值                                              |
| -------------------- | ---------------- | ------------ | ------------------------------------------------------- |
| 调拨任务编号         | `allocationNo`   | 是           | 5–30 个字符。                                           |
| 计划员               | `planner`        | 是           | 2–40 个字符。                                           |
| 发货仓               | `source`         | 是           | 北仓（`north`）、南仓（`south`）、东仓（`east`）。      |
| 配送等级             | `priority`       | 是           | 常规（`regular`）、优先（`priority`）。默认 `regular`。 |
| 计划发运日期         | `shipOn`         | 是           | 真实自然日，格式 YYYY-MM-DD。                           |
| 本车体积额度         | `shipmentCap`    | 是           | 1–10000000 的整数，单位为升。                           |
| 优先配送理由         | `priorityReason` | 按规则或选填 | 12–180 个字符。                                         |
| 已核对库存和收货地点 | `confirmed`      | 是           | 布尔值，初始未勾选。提交时必须勾选。                    |

## 收货点

至少 1 条、最多 12 条，各自有稳定 destinationId。在同一张单，去首尾空白并大写后的站点编号唯一。收货地址来自运营目录，表单只填写站点编号。卸货口交接要写库位编号，服务点不需要。

| 字段         | 交付键         | 必填         | 输入与存值                              |
| ------------ | -------------- | ------------ | --------------------------------------- |
| 收货站点编号 | `destination`  | 是           | 3–30 个字符。                           |
| 收货责任人   | `receiver`     | 是           | 2–40 个字符。                           |
| 交接方式     | `dock`         | 是           | 卸货口（`dock`）、服务点（`counter`）。 |
| 卸货口号     | `dockCode`     | 按规则或选填 | 2–24 个字符。                           |
| 收货交接说明 | `deliveryNote` | 按规则或选填 | 0–180 个字符。                          |

## 调拨明细

至少 1 条、最多 60 条。每行新增时分配稳定 lineId。站点编号作为业务关联，允许同一物品批次配送到不同站点。每行体积为件数乘单件计划体积，在试填时实时显示，交付保留升。

| 字段         | 交付键         | 必填         | 输入与存值                              |
| ------------ | -------------- | ------------ | --------------------------------------- |
| 库存物品编号 | `sku`          | 是           | 3–32 个字符。                           |
| 库存批次编号 | `lot`          | 是           | 3–32 个字符。                           |
| 目标站点编号 | `destination`  | 是           | 3–30 个字符。                           |
| 件数         | `units`        | 是           | 1–10000 的整数，单位为件。              |
| 单件计划体积 | `volumeLiters` | 是           | 1–10000 的整数，单位为升。              |
| 包装         | `flag`         | 是           | 常规（`standard`）、易碎（`fragile`）。 |
| 防损要求     | `packingNote`  | 按规则或选填 | 8–180 个字符。                          |

## 关联清理和编辑约束

删除仍被调拨行引用的站点时应阻止删除还是清空已有引用，仓库与调度团队尚未统一。把站点编号改成另一编号按删除旧编号增加新编号处理，旧引用同样清空。相同编号只改大小写或首尾空白时仍属于同一站点，所有引用保留。收货人、交接方式、备注变化也不清空引用。现存引用是否允许自动清空，等业务结论。

目标站点只接受当前单里已有的站点编号。工作态输入无效编号保留并提示使用已有站点，不能为了通过校验自动匹配其他站点。删除某个调拨行不会删除任何站点。增加空行后提交会提示逐行补齐。重排两张清单不改变既有行引用。

## 条件资料和数据保留

把卸货口改成服务点时，清除该站点的卸货口号，其他站点不受影响。易碎物品要求填写该行防损要求。切换到常规包装清除说明；再次进入易碎需要重新填写。清理只写对应行，不能清理另一个站点或产品的同名字段。

发货仓变化会改变库存含义，须重新核验整单。已有物品、批次和目标站点均保留，目录找不到则在具体行提示。换回原仓必须按当时库存重新核验，不能复用旧通过结果。

## 批次、库容与库存快照

同一个发货仓内按标准化 SKU 与批次组成库存池，所有目标站点的件数合计不得超过该池的可用库存。站点不同不能绕过总库存。重复的 SKU、批次、目标站点组合须合并到一行；冲突定位到两行的目标站点字段。重量不参与本样例额度计算。体积总额等于所有行整数升小计之和，不能超过本车体积额度。等于库存或车容边界可以交付。

库存服务按当前发货仓和发运日核对批次，反馈可用件数和站点可配送状态。库存不足给参与该池的行的件数标记错误，查无批次在该行批号提示。超体积提示挂到本车体积额度。遇到库区关停或目的地不接货，应对应发货仓或站点报告。所有服务错误保留工作值。

## 回包关联与预约

核验结果绑定原提交请求、仓库、日期及涉及的调拨行。用户提交前仍可编辑，相关字段变化会启动新的核验；后返回的旧结果不得恢复已清除引用、更改数量或放行新输入。只改交接备注可重新传递给交付服务，但不影响库存数量查验读集的实际意义。

点击预约以后，Host 核对完整校验结果并在服务端同一业务事务内保留库存额度和建立任务。若有别的单据占用了可用件数，保留本次录入并展示新的可用量，不创建半成功任务。客户端用调拨任务号、幂等键标识此次操作，重试时查询同一回执。预约成功返回任务编号以及每个站点的有序明细。为相同批次分配多个站点时，库存只扣合计件数一次。

## 约定的输出

站点清单按填写顺序交付。站点与物品编号统一去首尾空白并转大写，保留各自稳定 ID。每个调拨行输出所属站点编号、SKU、批次、件数、升数、包装和当前适用资料。总量字段由 Host 从同一已校验快照计算，不接收客户端输入的汇总数。优先级恢复常规的单据交付时省略理由，服务点交接省略卸货口号。

## 验收场景

1. 设置总可用 100 件，站点 A 45 件、B 55 件可通过；把 B 改为 56，两条都提示同一个批次库存不足。
2. 同一批次向 A 拆成 20 和 25 两行报重复；既有 A 45 与 B 55 两行允许并存。先改一行目标，再验证对应重复仅移除相关错误。
3. 删除已被三行引用的站点 B，预期是阻止删除还是允许并处理引用，待规则确认。A 的分配不受影响。
4. 站点 A 编号从 `a-29` 调整为 `A-29`，分配关系保留。
5. 两行各占 70 和 30 升，车容 100 升可过；把第二行加 1 升后，整单报超容量。数量减回来恢复通过。
6. 置为易碎后填写保护要求，清单删去另一行不影响该说明；切换为常规后说明清除，重新选易碎时说明为空。
7. 正在查询北仓批次时改选南仓，返回北仓库存不足的结果不覆盖南仓。南仓无该批次时仅在对应批次提示。
8. 预约调用返回前库存被先占用，给出当前库存并保持工作值。没有部分确认的站点，也没有半张任务单。
9. 预约成功的响应丢失，用原幂等键重试时返回原任务号；此次不会再次扣减库存。
