# 供应商月度对账与部分结算

采购财务按供应商对账单发起月度结算。一次受理对应一个采购主体、一个供应商、一份对账单与一个币种，允许包含多张原始凭证和跨凭证分别登记的冲销单。出账请求只登记拟入账记录和争议留待复核信息。付款审批、付款执行以及会计科目的分配在系统后续流程处理。

## 月度归属与交付模式

月份从 01 至 12。供应商应从当前主体的有效目录中选出，一份配置最多承接一个供应商。结算币种应用于全部行，人民币和港币均使用整数分录入。整单币种不由供应商默认值自动替换。

| 字段                     | 交付键          | 必填         | 输入与存值                                                        |
| ------------------------ | --------------- | ------------ | ----------------------------------------------------------------- |
| 结算期间                 | `periodCode`    | 是           | 月度期间 YYYY-MM，例如 2026-11。                                  |
| 结算经办人               | `operator`      | 是           | 2–40 个字符。                                                     |
| 采购主体                 | `entity`        | 是           | 港区采购（`harbor`）、总部采购（`central`）、门店采购（`mall`）。 |
| 供应商目录               | `supplier`      | 是           | 用编号或简称搜索；选项包含 id 和 label；出账只取供应商编号。      |
| 结算币种                 | `currency`      | 是           | 人民币（`cny`）、港币（`hkd`）。                                  |
| 对账单日期               | `statementDate` | 是           | 真实自然日，格式 YYYY-MM-DD。                                     |
| 本次交付方式             | `mode`          | 是           | 完整结算（`final`）、先结无争议金额（`partial`）。                |
| 部分结算说明             | `partialReason` | 按规则或选填 | 12–240 个字符。                                                   |
| 供应商对账单编号         | `statementRef`  | 是           | 4–40 个字符。                                                     |
| 已核对结算明细与冲销依据 | `acknowledged`  | 是           | 布尔值，初始未勾选。提交时必须勾选。                              |

## 原始凭证行

每单 1–50 行。每行有独立 voucherId；新增空行须完整填写或删除。凭证编号是匹配冲销的业务键；稳定行 ID 只用于编辑、错误和回执关联。原始凭证号按去首尾空白与统一大写后的字符串匹配。

| 字段             | 交付键         | 必填         | 输入与存值                                |
| ---------------- | -------------- | ------------ | ----------------------------------------- |
| 原始凭证编号     | `invoiceNo`    | 是           | 5–40 个字符。                             |
| 已验收单号       | `receiptNo`    | 是           | 5–36 个字符。                             |
| 凭证开具日       | `issuedOn`     | 是           | 真实自然日，格式 YYYY-MM-DD。             |
| 对账状态         | `status`       | 是           | 无争议（`clear`）、有争议（`disputed`）。 |
| 本次认领票面金额 | `faceMinor`    | 是           | 1–200000000 的整数，单位为分。            |
| 本次申请入账金额 | `appliedMinor` | 是           | 1–200000000 的整数，单位为分。            |
| 争议记录编号     | `disputeNo`    | 按规则或选填 | 4–32 个字符。                             |
| 争议说明         | `disputeNote`  | 按规则或选填 | 12–200 个字符。                           |
| 会计备注         | `invoiceNote`  | 按规则或选填 | 0–160 个字符。                            |

## 冲销凭证行

允许没有冲销，最多 30 行。每行有稳定 creditId。冲销金额使用正整数输入，计算净额时再扣减。冲销目标必须是本单中已录入且唯一的原始凭证。

| 字段           | 交付键           | 必填         | 输入与存值                                                               |
| -------------- | ---------------- | ------------ | ------------------------------------------------------------------------ |
| 冲销凭证编号   | `creditNo`       | 是           | 4–36 个字符。                                                            |
| 冲销目标凭证号 | `invoiceNo`      | 是           | 5–40 个字符。                                                            |
| 冲销金额       | `creditMinor`    | 是           | 1–200000000 的整数，单位为分。                                           |
| 冲销原因       | `reason`         | 是           | 已退货（`return`）、价格更正（`pricing`）、原单重复记账（`duplicate`）。 |
| 退货单编号     | `returnNo`       | 按规则或选填 | 5–36 个字符。                                                            |
| 价格批准号     | `priceApproval`  | 按规则或选填 | 5–36 个字符。                                                            |
| 会计说明       | `accountingNote` | 按规则或选填 | 8–180 个字符。                                                           |

## 主体与供应商目录

选择采购主体后开放供应商搜索。请求输入当前主体以及编号或简称关键字，返回有权在该主体下结算的有效供应商，结果对象包含编号 id 与显示名称 label。搜索无结果时可调整关键词，错误后允许重试，暂不影响其他已录字段。

切换主体时立即清掉供应商，即使两个主体共享同一供应商编号，也要求重新选择。更换供应商以及币种均保留既有录入供检查，但会重新核验关联；历史回包不可移除用户手工录入的凭证或放行新主体的资料。交付只取目录供应商编号。

## 录入局部校验

申报入账金额不能大于本次认领票面金额，不自动截断。凭证开具日不能晚于对账日；月份业务归属由关联验收单确认，允许上月开具的有效票据，只要验收单归属本期并符合财务服务的条件。凭证金额的单位必须保持为分，不接收浮点小数。

对账状态选有争议后，争议记录号及说明必填。恢复无争议时清除两个争议字段；再次选择有争议重新填写。改对账状态不能清除冲销行或修改它的金额。切换为部分结算须输入整单说明，恢复完整结算清除整单说明，保留各凭证原本的争议状态和记录。完整结算只在全单无争议时允许交付。有争议时换为部分结算或完成业务复核后重新提交。

## 冲销原因与关联

已退货要求提供退货单编号，价格更正要求价格批准号，原单重复记账要求说明为何冲销。三项资料各自独立，由原因控制显示与必填，改原因时清除上个原因的资料。主凭证是否有争议不影响冲销行能否填写，最终纳入本次结算由对账状态决定。

同一个原始凭证可被多条冲销凭证指向，但各冲销号必须唯一，按去空白及大写比较。本单原始凭证号重复时，所有冲突凭证行都提示，相关冲销目标报无法唯一匹配。删除有冲销引用的主凭证可以完成，但保留冲销行和手输目标号并标明失效，便于录入员决定是否删除冲销或改配到正确的原始凭证；不自动迁移到其他凭证。重新加入同一、且唯一的有效凭证后可重新通过引用检查。

## 整单净额与两种模式

部分结算时，有争议凭证及指向它的冲销行一起留待复核，并从本次净额及入账明细剔除。关联的退货或价格依据仍须在数据内正确并保留在争议留档。剩余可结算凭证至少有一条，不能生成只有争议留档没有入账数据的单据。

每张凭证的冲销金额合计最多为它的本次申请入账金额，等于允许，产生零净额。不能让其他正金额凭证抵消单张凭证的超额冲销。整单净额 = 所有纳入凭证的申请入账金额之和 − 所有纳入冲销行的金额之和。净额为零且有可结算凭证时允许交付；在生成出账请求前应让经办人复核本次金额汇总。对争议留档的金额单独展示，不能并入栏目的正式净额。

## 异步核验与写入资格

Host 校验器按当前主体、供应商、期间、币种、对账日期、结算模式和两类明细组成快照。财务服务确认每张验收单和凭证的供应商、币种、是否已入账及在本次期间的可结算余额。金额超出原凭证未结余额错误落到该笔申请入账金额。发票不属于供应商时错误落到相应凭证号。冲销凭证依据无效时保留行，并提示相应依据字段。重复编号错误定位到每个涉事编号，整单无可结算凭证时提示交付方式。

网络或服务超时视作核验未完成，当前工作值与现行同步错误保留。再次核验以当前版本为准，旧响应只能作为日志。校验返回后修改主体、币种、任一入账金额、争议状态、冲销号、任一被引用凭证、相关依据、结算模式，都需要重验。存在争议的条目既不会从工作值中自动删除，也不会暗中标为本次已结算。

## 确认、幂等和出账协议

按下送财务后，先完成现行本地和服务校验。Host 以服务复核后的同一输入快照计算及展示待确认摘要，它包含生效原始凭证计数和合计、冲销计数和合计、净额、被延后的凭证和冲销件数。用户只确认这份摘要绑定的版本。确认前任何影响摘要的编辑都使摘要失效，重算后再确认。

请求写入用主体编号、供应商编号、对账单号和本次提交键幂等。如果核验通过后另外的对账单刚占用某张凭证余额，服务在写入事务内返回新的错误，不准部分写入冲销或入账。网络错误时保留本地输入，按原键重试回查。允许用户根据错误修正工作值，修正后的新提交使用新键，旧成功回执仍可追溯。

## 最终输出与恢复

交付保留原录入顺序、币种、期间、主体、供应商编号、对账单号、日期、交付方式及当前适用说明；分开列交付和延后的两组凭证及冲销。每组包含稳定 ID 与标准化业务编号，账面金额单位为分。账务服务计算净额，Host 将该金额和提交回执显示给用户。浏览器页面设计可以显示短说明和布尔确认，批次核查结果和复核弹层由业务 Host 装配。

## 验收场景

1. 主体 A 搜到供应商 S01 后改主体 B，随后收到旧搜索结果，输入仍为空且不能从旧结果选择；新主体返回同号时须重新点选。
2. 已填两张原始凭证，申报 50,000 分和 60,000 分，分别冲销 5,000 分和 10,000 分。全部无争议时，两笔正式入账，净额 95,000 分。
3. 把第二张凭证标为争议并补编号与说明。完整结算阻止交付。切部分结算且填写说明后，正式金额为 45,000 分，保留第二张凭证和它的冲销于待复核记录。
4. 在部分结算中把第一张也标争议，提示没有可结算凭证。两张明细及冲销保留，不能提交零明细。
5. 一张凭证入账 60,000 分、冲销两条分别 25,000 和 35,000 时净额为 0 且可交付；第二条改为 35,001 分则该凭证超冲销，即使另一张正金额凭证仍足以让整单净额为正。
6. 对已退货冲销填写退货号后改为价格更正，原退货号清除，价格批准号必填；切回已退货不能恢复旧号。
7. 删除被两笔冲销引用的原凭证，两笔仍存在并以目标凭证号显示失效。重新添加匹配凭证后可重验，不生成新的冲销行 ID。
8. 票据核验发出后修改供应商或币种，旧回包不可放行。改动争议状态也使此前的正式结算摘要失效。
9. 同一份摘要确认两次且提交键相同，下游返回同一个回执；相同结算被其他批次抢占余额时，明确给出受影响行的新错误，全单完整保留。
10. 已录入票据的开户主体代表权限范围，目录请求只来自当前主体；更换经办人时核对新请求使用当前登录身份，成功回执仍关联当时提交记录。
