# 预期输出

沿用完整的 A 版 PRD。候选优先覆盖现有能力可以实现的规则。渠道核保与正式提交属于装载依赖。若确实缺少生成所必需的本地组件或函数，输出应指出具体能力、受影响需求和可继续试填的范围。

候选可预览时，优先验收以下场景：

1. 从投保人区修改本人护照号，再从第一名被保人卡片修改或清空。两处同步，其他家人的数据不变。
2. 添加家人至满六人。本人不可删除。删除第二人时，原第三人的身份资料和错误仍属于原第三人。
3. 本人与家人使用大小写或首尾空格不同的同一护照号。归一化后应提示两处冲突。
4. 让一名子女在起保日当天正满 18 岁。改动起保日跨过生日后，检查分类与监护声明的出现及清除。
5. 选择增强版，让一人在起保日满 70 岁。检查该人出现紧急联系人字段并报告计划冲突，原选计划保留。
6. 修改候选的「添加家人」文案，重新预览并保存，核对保存的是修订后的候选。

## 已观察的输出

在引入 `deferred_to_host` 之前，同一份 A 版 PRD 的查询合并前后各跑一次，均返回 `blocked`，均未调用编译器。Agent 当时报告过业务日期、护照归一化查重、核保和提交接入等缺口。这个结果记录历史回归点。调整后的 A 版实际结果待复验。
